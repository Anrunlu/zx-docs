# 算法课程文档模板与维护规则

算法课程的正文、标题、表格和代码排版由 `src/.vuepress/styles/index.scss` 共用维护。构建插件 `src/.vuepress/plugins/algorithm-documents.mjs` 根据课程目录自动添加排版类；文档无需复制 CSS 或添加客户端脚本。

本目录位于站点源码 `src` 之外，模板和编写提示不会生成教学页面。复制模板到课程目录后，应替换全部编写提示，再执行检查和生产构建。

## 选择模板

| 模板 | 用途 |
| --- | --- |
| `problem.md` | 一道题的详细题解，七章结构 |
| `lesson.md` | 一次课的贯穿讲义，串联题目与方法 |
| `guide.md` | 专题导学与课程概览，组织路线和题目入口 |

新文档在 frontmatter 设置 `algorithmDocType: problem`、`lesson` 或 `guide`。已经迁移的文档按相应规则检查；旧文档逐批迁移，不因尚未迁移而被强制重写章节。所有课程文档的本地引用均检查存在性和源码范围。

## 题目文档的写法

- 开头用一道具体问题引入，标明难度与核心方法，并给出三个可核对的学习目标及有效的前置知识链接。
- 二级标题固定为：题目描述、题目分析、实现代码、算法执行过程、复杂度分析、易错点、课堂练习。
- 分治讲子问题、边界和合并；动态规划讲状态、转移、初始化与遍历；贪心讲选择依据及证明；回溯讲状态、搜索分支、剪枝与撤销。方法差异放在三级标题中。
- Python 主实现完整、默认可见，输入约束、样例及输出与正文一致。补充实现可折叠，但每段代码应明确运行方式。
- 高亮使用 `python{行号范围}`，如 `python{13-18}`。语言名与花括号之间不加空格，避免被属性插件解释为普通 HTML 属性。
- 关键结论用 `::: tip`；具体易错提醒用 `::: warning`；补充细节与答案用 `::: details`。不要将全部正文包装成提示框。
- 执行过程围绕同一主示例，提供调用关系、状态表或图示。有现成动画时补充播放前、播放中、播放后的观察任务，并保留编号、颜色与状态说明。没有动画时用已有过程材料讲清，不放动画占位。
- 复杂度先给结论，再解释计数模型、时间及辅助空间；输出规模和大整数成本按题目需要区分。
- 练习分基础核对、过程推演和进阶思考，每题用独立的 `::: details 参考答案` 核对。

## 保留路径与元数据

修改已有文档时保持文件路径、作者、排序和有效的永久链接。保留已使用的章节锚点；如果确有必要改名，应显式保留旧锚点并核对引用。已有动画组件及运行资源继续留在站点源码中。

`scripts/algorithm-route-baseline.json` 保存推广前132篇课程文档的页面地址，以及首批18篇题目已有的章节锚点。新增文档可以增加页面，不要求删除旧地址。删除或迁移已有路径须作为单独、明确的变更处理，并有兼容方案；不能为绕过检查而直接更新基线。

同题出现在不同目录时，先核对其任务、方法与已有引用，再决定详细讲解与导引的关系。不要仅根据相似名称删除或重命名文件。

## 检查与交付

1. 运行 `pnpm run docs:check`，检查部署依赖、资源、已迁移文档的结构、元数据与本地引用。
2. 实际运行本次修改文档的 Python 示例，核对主输出、关键边界、过程与练习答案。构建脚本不执行文档中的任意 Python 代码。
3. 运行 `pnpm run docs:build`，在生产构建后核对页面地址、旧锚点、本地链接、字体和模板隔离。
4. 涉及组件、导入或资源变化时，在独立目录使用与 v6 锁文件兼容的 pnpm 8 冻结安装并构建；验证子路径发布，保持项目锁文件不变。
5. 所有新脚本、模板和运行资源随改动一起交付。
