# 木材加工

<Badge text="中等" type="tip" /> <Badge text="二分答案" type="tip" /> <Badge text="Python" type="tip" />

**切得出7段的长度可能有很多，怎样找到最大的114厘米？**

::: tip 本节学习目标
- **会建模：** 把最大长度问题转换为至少k段的可行性判断。
- **会追踪：** 根据段数的单调性决定二分方向。
- **会核对：** 核对闭区间更新、余料规则与无解时返回0的含义。

前置知识：整数除法与二分区间；可比较[快速幂](./二分法求幂.md)中的指数减半。
:::

## 题目描述

木材厂有 $n$ 根原木，第 $i$ 根的长度为 $L_i$ 厘米。现在需要把原木切成 $k$ 段等长的小木段，希望每段的长度尽可能大。求每段长度 $x$ 的最大值。

原木长度和小木段长度都必须是正整数。每根原木可以有剩余部分，原木之间不能拼接；按本题模型忽略切割损耗。如果能切出的等长木段多于 $k$ 段，可以只取其中的 $k$ 段。因此，判定某个长度是否可行时，要求的是**至少能切出 $k$ 段**。

如果连长度为1厘米的木段都不能得到 $k$ 段，输出0。这里的0表示没有可行的正整数长度，不表示真的切割出长度为0的木段。

### 输入与输出

- 第一行是两个正整数 `n`、`k`，分别表示原木数量和需要的小木段数量。
- 接下来 `n` 行，每行一个正整数 `L_i`，表示一根原木的长度。
- 输出一行，表示最大可行长度；如果不存在可行的正整数长度，输出 `0`。

数据范围：$1\leq n\leq 10^5$，$1\leq k\leq 10^8$，$1\leq L_i\leq 10^8$。

**样例输入：**

```text
3 7
232
124
456
```

**样例输出：**

```text
114
```

长度为114时，三根原木分别能切出2段、1段和4段，共7段；长度为115时，只能切出2段、1段和3段，共6段，因此最大长度为114。

另一个例子：原木长度为11和21，需要6段时，最大长度为5。两根原木分别能切出2段和4段，剩余部分可以不用。

## 题目分析

::: tip 核心结论
候选长度越大，可切段数越少或不变。可行时记录长度并向右搜索，不可行时向左搜索；判断条件是至少 $k$ 段，余料不能跨原木拼接。
:::

### 把求最大值转为判断是否可行

直接枚举每一种长度，再计算能切出的段数，可以找到答案，但原木最长可能达到 $10^8$，逐个尝试长度的代价太高。

先固定一个候选长度 $x\geq 1$。一根长度为 $L_i$ 的原木最多能切出 $\lfloor L_i/x\rfloor$ 段，全部原木最多能切出的段数为：

$$
C(x)=\sum_{i=1}^{n}\left\lfloor\frac{L_i}{x}\right\rfloor.
$$

定义 `can_cut(x)`：判断是否能切出至少 `k` 段长度为 `x` 的木段，即判断 $C(x)\geq k$。

代码中使用 `wood // x` 计算整段数量，余数对应不能再切出一整段的剩余部分。不能先把所有原木长度加起来再除以 $x$，因为不同原木的剩余部分不能拼接。

### 找出可行性的单调性

如果 $x_1<x_2$，对每根原木都有：

$$
\left\lfloor\frac{L_i}{x_1}\right\rfloor
\geq
\left\lfloor\frac{L_i}{x_2}\right\rfloor.
$$

因此，$C(x)$ 随着 $x$ 增大而单调不增：木段要求越长，能够切出的段数越少或保持不变。当最大可行长度处于候选范围内部时，可行性呈现“前面可行，后面不可行”的结构：

```text
候选长度：  1   2   3   ……   答案   答案+1   ……   最长原木长度
是否可行：  是  是  是  ……    是      否     ……       否
```

如果答案已经等于最长原木长度，整个候选范围都可行；如果连长度1都不可行，则整个范围都不可行，答案为0。

本题要找的是**最大的可行长度**，也就是可行区间的右端点。

可切段数可能一次减少多段，不一定出现 $C(x)=k$。例如原木为 `[8, 8]`、`k=3`：长度4时能切4段，长度5时只能切2段，答案仍然是4。因此，不能只寻找“恰好能切 $k$ 段”的长度。

### 设置边界与更新规则

设 $M=\max L_i$。一段木材不可能比最长的原木还长，所以候选答案范围是 `[1, M]`。使用闭区间二分，维护三个变量：

- `left`、`right`：仍需检查的候选长度区间，包含左右端点。
- `mid = (left + right) // 2`：本轮检查的长度。
- `answer`：已经检查过的最大可行长度，初始为0。

每轮分两种情况：

| 判断结果 | 能排除的候选长度 | 代码更新 | 原因 |
| --- | --- | --- | --- |
| `can_cut(mid)` 为真 | 不需要再检查不超过 `mid` 的长度 | `answer = mid`，`left = mid + 1` | 已经找到一个可行答案，继续寻找更长的木段 |
| `can_cut(mid)` 为假 | `mid` 及更大的长度都不可行 | `right = mid - 1` | 更长的木段只会切出更少或相同的段数 |

即使 $C(mid)=k$，也不能立即返回，因为更长的长度可能仍然能切出 $k$ 段。`answer = mid` 表示当前长度可以作为答案，随后继续向右搜索。

每次更新都排除了已经检查过的 `mid`，所以区间一定缩小。循环条件为 `left <= right`；当 `left > right` 时，剩余候选区间为空，返回 `answer`。

### 为什么答案正确

`answer` 始终是可行长度或初始的0。检查长度 `mid` 时，若它可行，不超过它的长度不会比已记录的答案更优，因此只需继续检查右侧；若它不可行，根据单调性，它及右侧全部不可行，可以整体排除。

每轮都保留了可能比 `answer` 更优的候选长度。区间清空后，不再存在更大的可行候选，记录的 `answer` 就是最大可行长度。如果所有候选长度都不可行，`answer` 保持0。

## 实现代码

### Python 二分答案实现

函数 `max_piece_length(woods, k)` 返回最大木段长度。参数 `woods` 是至少包含一个正整数的原木长度列表，`k` 是正整数；输入按题目的数据范围保证有效。

下面代码可以完整复制到 Python 文件中运行，并按题目的输入格式读取数据：

```python{17,18,19,20,21,23}
def max_piece_length(woods, k):
    """返回至少能切出 k 段时的最大正整数长度；无解时返回0。"""
    def can_cut(piece_length):
        pieces = 0
        for wood in woods:
            pieces += wood // piece_length
            if pieces >= k:
                return True     # 只需判断可行，不必继续计算完整段数
        return False

    left, right = 1, max(woods)
    answer = 0

    while left <= right:
        mid = (left + right) // 2
        if can_cut(mid):
            answer = mid
            left = mid + 1
        else:
            right = mid - 1

    return answer


print(max_piece_length([11, 21], 6))  # 5
print(max_piece_length([8, 8], 3))    # 4，能切4段时可以只取3段
print(max_piece_length([2, 3], 6))    # 0，长度1时也只有5段
print(max_piece_length([10], 1))      # 10
```

输入题目样例，输出为：

```text
114
```

单独调用这个函数，也可以验证以下输入：

```python
print(max_piece_length([11, 21], 6))  # 5
print(max_piece_length([8, 8], 3))    # 4，能切4段时可以只取3段
print(max_piece_length([2, 3], 6))    # 0，长度1时也只有5段
print(max_piece_length([10], 1))      # 10
```

不需要对原木排序：段数的计算只与每根原木的长度有关，二分上界通过 `max(woods)` 就能得到。`can_cut` 每次调用都会重新把 `pieces` 设为0，避免不同候选长度的段数互相影响。

### 一次可行性判断怎样计算

对样例原木 `[232, 124, 456]`，检查长度114和115：

| 候选长度 `x` | `232 // x` | `124 // x` | `456 // x` | 完整段数 `C(x)` | 是否至少7段 |
| --- | ---: | ---: | ---: | ---: | --- |
| 114 | 2 | 1 | 4 | 7 | 可行 |
| 115 | 2 | 1 | 3 | 6 | 不可行 |

长度114时，三根原木分别剩下4、10和0厘米；这些剩余部分不参与拼接。长度115时虽然仍有剩余木料，但不足以再从某一根原木中切出一整段115厘米的木段。

### 二分区间怎样逐轮缩小

下表完全按照主实现的闭区间规则执行。`left`、`right` 是本轮开始时的边界；段数列表示完整的 $C(mid)$，判定函数达到 `k` 后提前返回只影响计算量，不影响判断结果。

| 轮次 | `left` | `right` | `mid` | `C(mid)` | 是否可行 | 本轮更新 | 更新后的 `answer` |
| --- | ---: | ---: | ---: | ---: | --- | --- | ---: |
| 1 | 1 | 456 | 228 | 3 | 否 | `right = 227` | 0 |
| 2 | 1 | 227 | 114 | 7 | 是 | `left = 115` | 114 |
| 3 | 115 | 227 | 171 | 3 | 否 | `right = 170` | 114 |
| 4 | 115 | 170 | 142 | 4 | 否 | `right = 141` | 114 |
| 5 | 115 | 141 | 128 | 4 | 否 | `right = 127` | 114 |
| 6 | 115 | 127 | 121 | 5 | 否 | `right = 120` | 114 |
| 7 | 115 | 120 | 117 | 5 | 否 | `right = 116` | 114 |
| 8 | 115 | 116 | 115 | 6 | 否 | `right = 114` | 114 |

此时 `left = 115`，`right = 114`，循环结束，返回114。第2轮找到114时还不能立即停止；后续检查排除了所有更大的候选长度，才确认它是最大值。

### 没有可行长度时怎样结束

以 `[2, 3]`、`k=6` 为例：先检查长度2，只能得到2段，右边界变成1；再检查长度1，只能得到5段，右边界变成0。整个过程中没有可行候选，`answer` 一直是0，最终输出0。

与[快速幂](./二分法求幂.md)比较，可以看出两种“减半”的对象不同：

| 问题 | 每次缩小什么 | 决定下一步的依据 | 如何得到答案 |
| --- | --- | --- | --- |
| 快速幂 | 待求幂的指数 | 指数的奇偶性及幂的运算性质 | 子问题返回后，平方并按需补乘底数 |
| 木材加工 | 候选木段长度区间 | 某个长度能否切出至少 $k$ 段的单调判定 | 找到最大的可行候选长度 |

## 复杂度分析

### 先看结论

按整数除法与比较为单位成本；$n$ 为原木数，$M$ 为最长原木长度。

| 实现或任务 | 时间复杂度 | 辅助空间复杂度 |
| --- | --- | --- |
| 二分计算函数，不含输入列表 | $O(n\log(M+1))$ | $O(1)$ |
| 含输入列表的完整程序 | $O(n\log(M+1))$ | $O(n)$ |


设原木数量为 $n$，最长原木长度为 $M=\max L_i$。在题目的整数范围内，按一次整数除法、加法和比较为常数时间的模型分析。

### 时间复杂度

一次 `can_cut` 最多检查 $n$ 根原木，时间为 $O(n)$。提前返回可能减少实际检查次数，最坏情况下仍需扫描全部原木。

候选区间从 `[1, M]` 开始，每轮约减半，最多进行 $\lfloor\log_2 M\rfloor+1$ 轮检查。统一包含 $M=1$ 的情况，总时间复杂度可写为 $O(n\log(M+1))$，通常简写为 $O(n\log M)$。

当 $M\leq 10^8$ 时，最多检查27个候选长度。枚举所有整数长度则需要 $O(nM)$ 的时间。

本题每轮要计算可切段数，因此时间复杂度不能只写成 $O(\log M)$。这里 $n$ 表示原木数量，与快速幂文档中表示指数的 $n$ 含义不同。

### 辅助空间复杂度

二分函数只维护边界、候选长度、答案和段数等固定数量的变量，使用循环实现，辅助空间为 $O(1)$。保存输入的原木列表需要 $O(n)$ 空间，因此包含输入存储的程序空间为 $O(n)$。

不进行排序，避免了额外的排序开销；可行性判断也不需要真正创建或保存切出来的木段。

## 易错点

| 易错点 | 正确理解 |
| --- | --- |
| 只在可切段数等于 `k` 时返回真 | 应判断 `pieces >= k`，多出来的段可以不取 |
| 达到 `k` 段就把当前长度当成最终答案 | 这只说明当前长度可行，还要继续向右找更长的长度 |
| 用 `sum(woods) // x` 计算段数 | 应逐根计算 `wood // x` 再相加，剩余部分不能拼接 |
| 从长度0开始判断 | 检查范围从1开始，避免除以0；0仅作为无解时的返回值 |
| 可行时缩小右边界 | 本题求最大可行长度，可行时应增大左边界 |
| 写成 `left = mid` 或 `right = mid` | 本文的闭区间模板应使用 `mid + 1` 或 `mid - 1`，确保区间缩小 |
| 没有保存 `answer` | 当前候选可行时记录它；后续候选不可行也不能丢掉已经找到的答案 |
| 在多次检查之间累计段数 | 每次 `can_cut` 都从 `pieces = 0` 开始 |
| 认为必须先排序才能二分 | 二分的是候选长度，原木列表不需要有序 |
| 把二分轮数当成整体运行时间 | 每轮还要扫描原木，最坏时间为 $O(n\log(M+1))$ |

## 课堂练习

先独立作答，再逐题展开答案核对。

### 基础核对

**1.** 原木为 `[2, 3]`，需要6段，最终返回多少？哪一个候选长度能确认没有正整数解？

::: details 参考答案

返回0。长度1也只能切出 `2 + 3 = 5` 段，所有更大的长度都不可能满足要求。

:::

**2.** 原木为 `[10]` 时，需要1段、3段和11段，答案分别是多少？

::: details 参考答案

分别为10、3、0。

:::

### 过程推演

**3.** 原木为 `[11, 21]`，需要6段。分别计算长度5和6的可切段数，说明最大长度是多少。

::: details 参考答案

长度5时为 `11 // 5 + 21 // 5 = 2 + 4 = 6`；长度6时为 `1 + 3 = 4`，最大长度为5。

:::

**4.** 原木为 `[8, 8]`，需要3段。为什么条件必须写成“至少3段”，而不能要求“恰好3段”？

::: details 参考答案

长度4能切4段，可以只取3段，因此4可行；长度5只能切2段，答案为4。这个例子没有恰好能切3段的整数长度，只判断相等会漏掉正确答案。

:::

**5.** 在原样例中，为什么第2轮得到 `C(114) = 7` 后还要继续搜索？

::: details 参考答案

等于7段只说明114可行，不能凭这个判断更长的长度是否也可行。后续二分需要排除所有更大的候选；本例最终确认115不可行，结合单调性才确定最大值为114。

:::

### 进阶思考

**6.** 原木为 `[5, 5]`，候选长度为3时，`sum(woods) // 3` 与逐根计算再相加分别是多少？哪一种符合题意？

::: details 参考答案

前者是 `10 // 3 = 3`，后者是 `5 // 3 + 5 // 3 = 1 + 1 = 2`。逐根计算才符合题意，两个剩余的2厘米不能拼成一段3厘米木材。

:::
