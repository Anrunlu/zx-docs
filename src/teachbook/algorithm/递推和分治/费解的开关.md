# 费解的开关

## 题目描述

$25$ 盏灯排成一个 $5\times5$ 的方阵，每盏灯有一个开关。灯亮记为 `1`，灯灭记为 `0`。按下一盏灯的开关时，这盏灯以及它上下左右相邻的灯都会改变状态；超出方阵边界的位置忽略。

给定若干组初始状态。对每组状态，求最少按多少次开关可以使所有灯都亮起。每组最多按 **6 次**；如果无法在6次以内完成，输出 `-1`。同一个开关重复按两次会抵消，因此无需在方案中重复按同一个开关。

输入第一行是游戏组数 $n$，接下来每组包含5行、每行5个字符，字符只含 `0` 和 `1`。组与组之间可以有空行。题目约束为 $0<n\leq500$。

**示例：**

```text
输入：
3
00111
01011
10001
11010
11100

11101
11101
11110
11111
11111

01111
11111
11111
11111
11111

输出：
3
2
-1
```

第一组最少按3次；第二组最少按2次；第三组不能在6次以内点亮全部灯。

## 题目分析

### 按行推导必需的操作

直接尝试每个位置按不按，需要考虑 $2^{25}$ 种情况。利用开关只影响自身和相邻位置的规则，可以把搜索范围缩小。

从第一行开始逐行处理。假设当前已经决定了第一行的按法：检查第一行每盏灯的最终状态。如果某盏灯仍然熄灭，为了点亮它，只能按它正下方的开关。按其他开关都不能改变这一行已经确定的灯。

因此，第一行的按法确定后，第二行的按法就被迫确定；第二行确定后，第三行也随之确定。依此处理前四行，最后检查第五行是否全部点亮。此时第四行已经处理完成；再按第五行的开关会改变第四行的灯，因此不能用它们额外修正第五行，只能检查第五行是否全亮。

### 枚举第一行的所有可能

第一行有5个开关，每个开关有“按”或“不按”两种选择，共有 $2^5=32$ 种方案。用整数 `mask` 的低5位表示第一行的按法：第 `col` 位为1，就按第一行第 `col+1` 列的开关。

对每种方案执行以下步骤：

1. 复制初始棋盘，并执行 `mask` 对应的第一行操作。
2. 从上到下扫描前四行；若当前行某格为0，就按它正下方的开关。
3. 检查最后一行是否全为1。若是，统计本方案按键次数并更新最少次数。
4. 所有32种第一行方案都处理完后，若最少次数大于6，返回 `-1`。

按开关相当于对相应格子执行异或 `^= 1`：0变1，1变0。每按一次会改变自身和最多四个邻居。

### 为什么只枚举第一行就够

任意可行方案都包含一种确定的第一行按法，而算法会枚举这32种情况中的每一种。第一行固定后，为了让第一行全亮，第二行的按法是唯一确定的；继续向下，每一行的按法也都由上一行的状态唯一确定。因此，对每种第一行方案，算法生成了唯一可能使前四行全亮的后续操作。最后一行的检查可以判断该方案是否真的点亮了整个棋盘。

算法既不会漏掉可行方案，也不会把未点亮最后一行的方案误判为成功；在所有成功方案中取按键次数最少者，即得到题目要求的答案。

## 实现代码

下面的程序从标准输入读取多组棋盘，并按题目格式逐行输出答案。函数 `min_flips` 返回最少按键次数；若最少次数超过6，则返回 `-1`。

```python
import sys


def toggle(board, row, col):
    """按下 (row, col)，翻转它自身和上下左右相邻的灯。"""
    for dr, dc in ((0, 0), (1, 0), (-1, 0), (0, 1), (0, -1)):
        next_row = row + dr
        next_col = col + dc
        if 0 <= next_row < 5 and 0 <= next_col < 5:
            board[next_row][next_col] ^= 1


def min_flips(rows):
    """返回点亮 5×5 棋盘的最少按键次数；超过 6 次时返回 -1。"""
    best = 26  # 5×5 的开关最多各按一次，26 可作为无解标记

    for mask in range(1 << 5):  # 枚举第一行的 32 种按法
        board = [[int(light) for light in line] for line in rows]
        presses = 0

        # mask 的第 col 位决定是否按第一行第 col 列。
        for col in range(5):
            if mask & (1 << col):
                toggle(board, 0, col)
                presses += 1

        # 当前行若有熄灭的灯，只能按它正下方的开关。
        for row in range(4):
            for col in range(5):
                if board[row][col] == 0:
                    toggle(board, row + 1, col)
                    presses += 1

        if all(light == 1 for light in board[4]):
            best = min(best, presses)

    return best if best <= 6 else -1


def solve():
    # 忽略空行，按组读取棋盘；每次只保留当前棋盘。
    lines = (line.strip().decode() for line in sys.stdin.buffer if line.strip())
    first_line = next(lines, None)
    if first_line is None:
        return

    game_count = int(first_line)
    for _ in range(game_count):
        rows = [next(lines) for _ in range(5)]
        print(min_flips(rows))


if __name__ == "__main__":
    solve()
```

用题目样例运行，输出：

```text
3
2
-1
```

`toggle` 的行列下标从0开始；题目描述中的第一行第一列对应 `toggle(board, 0, 0)`。复制棋盘后再尝试每个 `mask`，可避免不同方案相互影响。

### 例一：固定第一行按法后逐行推导

对样例第一组，初始棋盘为：

```text
00111
01011
10001
11010
11100
```

枚举到第一行只按第1列（`mask` 的第0位为1）时，按键次数为1。按完后棋盘是：

```text
11111
11011
10001
11010
11100
```

第一行已经全亮。检查第二行时，第3列仍为0，只能按它正下方的开关，也就是第3行第3列。此时棋盘变为：

```text
11111
11111
11111
11110
11100
```

接着检查第四行，第5列为0，只能按第五行第5列。最终状态为：

```text
11111
11111
11111
11111
11111
```

这一方案共按了3次：第一行第1列、第三行第3列、第五行第5列。继续检查其余第一行方案，发现不存在少于3次的成功方案，因此第一组答案为3。

| 处理步骤 | 检查的行 | 发现的熄灭位置 | 被迫按下的位置 | 累计按键数 |
| --- | ---: | --- | --- | ---: |
| 枚举第一行 | 1 | — | 第1行第1列 | 1 |
| 向下推导 | 2 | 第2行第3列 | 第3行第3列 | 2 |
| 向下推导 | 4 | 第4行第5列 | 第5行第5列 | 3 |
| 检查结果 | 5 | 无 | 无 | 3 |

注意：检查到某行时，按键位置在它正下方；被按下的开关会同时影响该行、下一行及左右邻格。处理完一行后，不再回头更改这一行。

### 例二：枚举与强制操作的边界

第二组样例中，可以找到一种两次按键的成功方案：第一行第5列，以及第二行第5列。第一行按法确定之后，第一行已经全亮；向下检查时，只有第二行第5列需要由它正下方的开关修正，最后一行也全部点亮。算法会比较所有32种第一行按法，输出最少次数2。

对于第三组样例，32种第一行按法经过逐行推导后，都无法在6次以内使最后一行全亮，因此输出 `-1`。

## 复杂度分析

设棋盘边长为 $m$；本题固定 $m=5$。每个第一行方案最多扫描 $m(m-1)$ 个位置，按键翻转只涉及常数个格子；第一行方案数为 $2^m$。

### 时间复杂度

每组棋盘需要 $O(2^m\cdot m^2)$ 时间。由于本题 $m=5$ 固定，每组只需检查32种方案、扫描至多100个位置，故每组耗时是固定上限；$n$ 组数据总计为 $O(n\cdot2^m\cdot m^2)$，本题中等价于 $O(n)$。

### 辅助空间复杂度

每次枚举都会复制一个 $m\times m$ 棋盘，额外空间为 $O(m^2)$；本题固定5×5，因此每组算法辅助空间为 $O(1)$。程序逐组读取和处理，不把所有棋盘同时存入内存。

## 易错点

| 易错点 | 正确理解 |
| --- | --- |
| 枚举全部25个开关 | 需要枚举的只有第一行5个开关，共32种；后续操作由上一行状态决定 |
| 熄灭时按同一行的开关 | 应按正下方的开关，才能修正当前格并保持之前的行不再变化 |
| 处理最后一行时还尝试往下按 | 最后一行没有下一行开关可用；它只能用于检查方案是否成功 |
| 按一次只改变被按的灯 | 自身和上下左右有效邻格都要翻转，边界外的位置忽略 |
| 棋盘按字符做异或 | 先将字符转为整数0/1；整数异或 `^= 1` 才能切换状态 |
| 每次枚举都继续使用上次修改后的棋盘 | 每种第一行按法都必须从初始棋盘副本开始 |
| 只判断是否有解，没有取最小值 | 所有成功方案都要统计按键次数，并更新最小值 |
| 找到解就认为满足题意 | 输出最少次数；如果最少次数大于6，仍须输出 `-1` |
| 用 `mask` 位序时行列混淆 | `mask` 的第 `col` 位对应第一行第 `col` 列，列下标从0开始 |

## 课堂练习

1. 为什么第一行只需要枚举32种按法，而不需要枚举整个棋盘的 $2^{25}$ 种按法？
2. 对样例第一组，当第一行只按第1列时，后续被迫按下哪两个开关？最终按键次数是多少？
3. 假设棋盘扩展为 $m\times m$，第一行枚举多少种状态？算法时间复杂度如何表示？
4. 如果 `toggle` 忘记翻转被按开关自身，只翻转上下左右，会破坏哪一项题目规则？

::: details 参考答案
1. 第一行只有5个开关，所以有 $2^5=32$ 种选择。第一行固定后，为点亮当前行，每个熄灭位置只能按它正下方的开关，后续各行的按法都被确定。
2. 先按第1行第1列；之后按第3行第3列和第5行第5列。总共3次，最终全亮。
3. 第一行有 $2^m$ 种按法。每种方案最多处理 $O(m^2)$ 个格子，所以时间复杂度为 $O(2^m m^2)$。
4. 题意规定按键会改变灯自身的状态，也会改变相邻灯。漏掉自身翻转后，模拟的开关行为就与题目不符，按键次数和最终状态都会错误。
:::
