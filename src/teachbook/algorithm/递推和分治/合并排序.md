# 合并排序

<Badge text="基础" type="tip" /> <Badge text="分治与归并" type="tip" /> <Badge text="Python" type="tip" />

**把两个已经有序的小数组合并，怎样一步步得到整个数组的顺序？**

::: tip 本节学习目标
- **会建模：** 把排序任务分解成左右两个较小排序任务。
- **会追踪：** 用双指针解释线性合并与稳定性。
- **会核对：** 比较总工作量、递归深度和中间列表的空间。

前置知识：列表、下标与递归；可先阅读[同时求最大值与最小值](./同时求数组的最大值与最小值.md)。
:::

## 题目描述

给定一个整数列表 `nums`，使用合并排序（也称归并排序）将它按非递减顺序排列，并返回一个新列表。非递减顺序允许相邻元素相等；原列表保持不变。列表可以为空，也可以包含重复值或负数。

不得调用 Python 内置排序函数（如 `sort()`、`sorted()`）。要求排序具有**稳定性**：数值相等的元素，在结果中的相对先后顺序与输入一致。正文使用0开始的列表下标，设输入元素个数为 $n$。

**示例：**

```text
输入： [5, 2, 3, 1]
输出： [1, 2, 3, 5]

输入： [5, 1, 1, 2, 0, 0]
输出： [0, 0, 1, 1, 2, 5]

输入： [3, -1, 2, -1, 0]
输出： [-1, -1, 0, 2, 3]
```

长度为0时返回空列表；长度为1时返回含该元素的新列表。长度为奇数时也要正常排序，不要求输入长度是2的幂。

## 题目分析

::: tip 核心结论
递归负责让左右两段分别有序，双指针负责合并。相等时优先取左侧元素，保留原有相对顺序；当前层需要线性处理元素。
:::

### 将排序问题拆成更小的排序问题

直接对整个数组反复寻找最小值并放到前面，可能需要多轮扫描。合并排序使用分治思想：先把数组分成左右两段，分别排好序，再把两个有序段合并成一个有序数组。

例如 `[5, 2, 3, 1]` 先分成 `[5, 2]` 和 `[3, 1]`，再继续对半拆分，直到每段只剩一个元素。单个元素天然有序，因此递归可以从长度为1的子数组开始返回。

### 定义函数、边界与递推关系

定义 `merge_sort(nums)`：返回 `nums` 中所有元素按非递减顺序排列的新列表。这里的“非递减”允许相邻元素相等。

- **边界条件：** 长度不超过1时，直接返回列表副本。空列表和单元素列表都已经有序。
- **拆分步骤：** 取 `mid = len(nums) // 2`，左半段为 `nums[:mid]`，右半段为 `nums[mid:]`。例如长度5拆成长度2和3，两段不重叠，也不遗漏中间元素。
- **递归步骤：** 分别递归排序左右两段。
- **合并步骤：** 从左右有序列表的当前位置开始比较，较小者加入结果；一侧耗尽后，把另一侧剩余元素依次加入。

与[快速幂](./二分法求幂.md)一样，每次递归都会将规模约减半。但快速幂只需求一个半次幂并复用结果；合并排序必须分别排序左右两个不同的子列表。因此这里有**两次子调用**，而合并操作还要线性地处理两个子列表的元素。

若数组长度为 $n$，左右两段长度分别约为 $n/2$，递推式为：

$$
T(n)=T(\lfloor n/2\rfloor)+T(\lceil n/2\rceil)+O(n),\qquad T(0),T(1)=O(1).
$$

递推式描述的是运行时间，不是排序结果的数值关系。每次拆分都会让子问题规模约减半，时间与空间的具体推导见后文。

### 用两个索引合并有序列表

`merge(left, right)` 接收两个已经有序的列表。索引 `i`、`j` 分别指向左右列表中第一个尚未取出的元素，`result` 保存已取出的有序前缀。

每次比较 `left[i]` 和 `right[j]`，把较小者追加到 `result`，只移动取出元素那一侧的索引。若值相等，取左侧；若一侧耗尽，另一侧的剩余元素已经有序，直接接到结果末尾，无需继续逐对比较。

### 合并为什么能得到有序结果

合并时，左右两段各自已经有序，因此左段当前元素是左段剩余元素的最小值，右段当前元素是右段剩余元素的最小值。每次取两者较小者，就是所有剩余元素中的最小值。这样始终保持：`result` 有序，且其中的元素不大于尚未取出的元素。循环结束后接上剩余部分，得到包含全部输入元素的有序列表。

整个排序也可以由小问题向大问题证明：长度不超过1时直接正确；若左右递归调用都正确，合并又能得到正确结果，那么当前调用也正确。递归不断缩小规模并最终到达边界，所以整个算法正确。

对于稳定性，左右两段内部的顺序由递归保证；跨越左右两段的相等元素，原来左段元素就在右段元素之前。合并时相等先取左侧，便保留了这一顺序。

## 实现代码

### Python 递归实现

下面的程序可以独立运行。`merge_sort` 负责拆分与递归，`merge` 负责合并；两者共同实现题目要求。

```python{6,7,8,19,20,21,23,24}
def merge_sort(nums):
    """返回 nums 的升序副本，不修改原列表。"""
    if len(nums) <= 1:
        return nums.copy()

    mid = len(nums) // 2
    left = merge_sort(nums[:mid])
    right = merge_sort(nums[mid:])

    return merge(left, right)


def merge(left, right):
    """将两个已升序排列的列表合并为一个升序列表。"""
    result = []
    i = j = 0

    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1

    # 每次只会有一侧还剩元素；extend 将其全部接到结果末尾。
    result.extend(left[i:])
    result.extend(right[j:])
    return result


if __name__ == "__main__":
    nums = [5, 2, 3, 1]
    sorted_nums = merge_sort(nums)
    print("排序结果：", sorted_nums)
    print("原数组：", nums)

    print("空列表：", merge_sort([]))
    print("单元素：", merge_sort([7]))
    print("含重复值：", merge_sort([5, 1, 1, 2, 0, 0]))
    print("奇数长度与负数：", merge_sort([3, -1, 2, -1, 0]))
```

输出：

```text
排序结果： [1, 2, 3, 5]
原数组： [5, 2, 3, 1]
空列表： []
单元素： [7]
含重复值： [0, 0, 1, 1, 2, 5]
奇数长度与负数： [-1, -1, 0, 2, 3]
```

`merge` 的前提是输入的 `left` 和 `right` 已经分别升序排列；`merge_sort` 负责通过递归保证这个前提。代码使用索引向前移动，不使用 `pop(0)` 删除列表首元素，避免每次删除都搬移后续元素。切片、`copy()` 和合并都创建新列表，所以即使输入为空或只有一个元素，返回值也不会与原列表是同一个列表对象。

### 示例与调用顺序

以 `nums = [5, 2, 3, 1]` 为例，递归先一路拆分到单元素列表，再按返回顺序合并。

### 递归调用：不断拆分

```text
merge_sort([5, 2, 3, 1])
├── merge_sort([5, 2])
│   ├── merge_sort([5])  → [5]
│   └── merge_sort([2])  → [2]
│   合并 [5] 与 [2]      → [2, 5]
└── merge_sort([3, 1])
    ├── merge_sort([3])  → [3]
    └── merge_sort([1])  → [1]
    合并 [3] 与 [1]      → [1, 3]

合并 [2, 5] 与 [1, 3]    → [1, 2, 3, 5]
```

图中的树形分支表示调用关系。程序按深度优先顺序执行：先完成整个左分支，再完成整个右分支，最后合并左右结果；不是先同时拆分所有分支，再一起合并。递归到长度1时停止，合并从最深层开始，逐层构造更长的有序数组。

### 递归返回：逐步合并

| 合并的左右有序段 | 取出或追加的元素顺序 | 合并结果 |
| --- | --- | --- |
| `[5]` 与 `[2]` | 2、5 | `[2, 5]` |
| `[3]` 与 `[1]` | 1、3 | `[1, 3]` |
| `[2, 5]` 与 `[1, 3]` | 1、2、3，最后接上5 | `[1, 2, 3, 5]` |

### 双指针：最后一次合并的状态变化

最后一次合并中，`left = [2, 5]`、`right = [1, 3]`，初始 `i = j = 0`。表中的索引和结果均为本步完成后的状态：

| 步骤 | 本步比较或操作 | `i` | `j` | `result` |
| --- | --- | ---: | ---: | --- |
| 1 | 比较2和1，取右侧1 | 0 | 1 | `[1]` |
| 2 | 比较2和3，取左侧2 | 1 | 1 | `[1, 2]` |
| 3 | 比较5和3，取右侧3 | 1 | 2 | `[1, 2, 3]` |
| 4 | 右侧耗尽，追加 `left[1:]`，即 `[5]` | 1 | 2 | `[1, 2, 3, 5]` |

第4步使用 `extend`，不会再移动 `i` 或 `j`；此时函数已不需要继续比较。最后一次合并进行了3次元素比较，加上前两次合并各1次，这个例子共进行了5次元素比较。追加剩余元素仍需要复制，但不需要逐对比较。

### 相等元素：观察稳定性

为区分相等元素，给输入 `[4, 2, 2, 1]` 中的两个2标上标签，记为 `[4, 2甲, 2乙, 1]`。标签只用来观察先后，比较时只看数值：

```text
左段排序： [4, 2甲] → [2甲, 4]
右段排序： [2乙, 1] → [1, 2乙]
最后合并： 先取1，再取2甲，再取2乙，最后接上4
排序结果： [1, 2甲, 2乙, 4]
```

当 `2甲` 与 `2乙` 比较时，`<=` 让左侧的 `2甲` 先加入结果，因此保持输入中的先后顺序。只观察普通整数列表中的两个2，无法区分它们的身份；标签使稳定性的含义更清楚。

## 复杂度分析

### 先看结论

按元素比较、读取和复制为单位成本；$n$ 为元素数，0或1个元素的处理为常数时间。

| 实现或任务 | 时间复杂度 | 辅助空间复杂度 |
| --- | --- | --- |
| 归并排序，n≥2 | $O(n\log n)$ | $O(n)$ |


按元素比较、复制和写入次数计数，假设一次元素比较、列表索引和元素复制耗时为常数，`append` 按摊还常数时间计费。列表切片和 `extend` 按涉及的元素个数计费。令 $n$ 为输入元素个数；以下对数级结论针对 $n\geq2$，空列表和单元素列表直接返回，时间与空间均为常数级。

### 时间复杂度

数组大致每次对半拆分，形成 $O(\log n)$ 层。在同一层，各子问题处理的元素互不重叠，总长度不超过 $n$；所有合并与切片的工作量合计为 $O(n)$。因此总时间复杂度为 $O(n\log n)$。

当 $n$ 是2的幂时，可以把运行时间递推式简写为：

$$
T(n)=2T(n/2)+O(n).
$$

即使输入已经有序，这份实现仍然递归拆分、复制并合并全部元素。因此最好、平均和最坏情况下的时间都是 $\Theta(n\log n)$；比较次数可能随输入改变，整体数量级不变。这里没有增加“已排好序就跳过合并”的优化。

**递归深度不能直接代表总时间。** 对非空输入，调用树有 $n$ 个单元素叶子，每个内部调用都有两个子调用，共有 $2n-1$ 次 `merge_sort` 调用；每条调用链的深度却只有 $O(\log n)$。快速幂每层只有一次子调用，而合并排序要汇总整棵调用树上的工作。

### 辅助空间复杂度

合并时需要结果列表保存元素，额外列表空间峰值为 $O(n)$。递归按深度优先执行：沿当前调用链保留的子列表长度大致为 $n,n/2,n/4,\ldots$，几何级数的和为 $O(n)$；已完成的左侧结果和当前合并列表也只增加常数倍的线性存储。剩余切片 `left[i:]`、`right[j:]` 会短暂占用额外列表空间，但不改变数量级。

递归栈深度为 $O(\log n)$，因此总辅助空间为 $O(n)$。即使把最终返回的列表单独视为输出空间，中间列表仍占 $O(n)$ 辅助空间。辅助空间统计**同一时刻仍需保留的存储峰值**，不能把整个执行期间每次创建的列表长度累加成 $O(n\log n)$。

该实现返回新列表，不会修改输入。虽然一些原地归并实现可以改变空间使用方式，但它们需要更复杂的索引与数据搬移；本题代码优先清楚展示分治和合并过程。

## 易错点

| 易错点 | 正确理解 |
| --- | --- |
| 只拆分，不合并 | 拆分只产生小问题；必须在递归返回时合并左右有序结果 |
| 认为长度为1还要继续拆分 | 单元素列表已经有序，是递归终止条件 |
| 边界只写 `len(nums) == 1` | 空列表也要停止递归，使用 `len(nums) <= 1` |
| 左右切片都包含或都遗漏 `mid` | 使用 `nums[:mid]` 和 `nums[mid:]`，保证不重复、不遗漏 |
| 合并时只比较一次 | 每取出一个元素都要移动相应一侧的索引，直到某一侧耗尽 |
| 取出一侧元素后两个索引都加1 | 只移动被取出元素那一侧的索引，否则会漏掉元素 |
| 忘记接上剩余元素 | 一侧耗尽后，另一侧的剩余部分仍需加入结果 |
| 相等时先取右边元素 | 用 `<=` 先取左边，才能保证稳定性 |
| 使用 `pop(0)` 取列表首项 | 首项删除会搬移后续元素，反复删除可能使合并步骤退化；使用索引即可 |
| 把每层的 $O(n)$ 误认为总时间也是 $O(n)$ | 共有 $O(\log n)$ 层，每层总工作量为 $O(n)$，总计 $O(n\log n)$ |
| 误认为递归栈是 $O(n)$ | 子数组规模每层约减半，最大递归深度为 $O(\log n)$；总辅助空间 $O(n)$ 来自列表存储 |
| 把各次列表分配量累加后当作辅助空间 | 辅助空间计算同时存活的峰值，本实现为 $O(n)$ |

### 基础核对

**1.** 合并 `[1, 4, 7]` 和 `[2, 4, 6]` 时，依次比较并取出的元素是什么？最终结果是什么？

::: details 参考答案

比较后依次取出1、2、4（左侧）、4（右侧）、6，最后接上7；结果为 `[1, 2, 4, 4, 6, 7]`。

:::

### 过程推演

**2.** 手动对 `[8, 3, 6, 2]` 画出拆分过程，并按递归返回顺序写出每次合并的结果。

::: details 参考答案

拆分为 `[8, 3]` 和 `[6, 2]`，再拆成 `[8]`、`[3]`、`[6]`、`[2]`。依次合并得到 `[3, 8]`、`[2, 6]`，最后合并为 `[2, 3, 6, 8]`。

:::

**3.** 对 `[3, -1, 2, -1, 0]`，第一层拆分得到什么？左右排序结果和最终结果分别是什么？

::: details 参考答案

第一层 `mid = 2`，拆成 `[3, -1]` 和 `[2, -1, 0]`。左右排序结果为 `[-1, 3]` 和 `[-1, 0, 2]`，最终为 `[-1, -1, 0, 2, 3]`。

:::

### 进阶思考

**4.** 为什么归并时使用 `left[i] <= right[j]` 可以保证稳定？如果改为 `<`，会有什么变化？

::: details 参考答案

两侧元素相等时先取左侧，保留它们进入当前子数组之前的相对顺序。改为 `<` 后相等时会先取右侧，因此不能保证稳定；排序数值仍然正确。

:::

**5.** 若每层合并总共处理 $n$ 个元素，递归共有约 $\log_2 n$ 层，推导总时间复杂度。

::: details 参考答案

每层 $O(n)$，共 $O(\log n)$ 层，所以 $T(n)=O(n\log n)$。

:::

**6.** 如果在合并循环中用 `left.pop(0)` 取元素，为什么不能再直接把单次合并视为线性时间？

::: details 参考答案

Python 列表从开头删除元素时，需要把后续元素向前移动，单次可能花费线性时间。若反复删除，长度为 $m$ 的一次合并最坏可累计 $O(m^2)$ 移动；用索引让每个元素只读取、追加一次，合并才是 $O(m)$。

:::

**7.** 长度为4时，本实现调用 `merge_sort` 几次？若列表已经升序排列，是否可以把时间复杂度写成 $O(n)$？

::: details 参考答案

共 $2\times4-1=7$ 次调用：1个长度4的调用、2个长度2的调用和4个长度1的调用。已经有序时仍执行全部拆分、复制和合并，时间仍为 $\Theta(n\log n)$。

:::
