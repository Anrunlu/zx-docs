# 合并排序

## 题目描述

给定一个整数数组 `nums`，请将它按升序排列并返回排序结果。数组可以为空，也可以包含重复值或负数。不得调用 Python 内置排序函数（如 `sort()`、`sorted()`）；要求使用合并排序思想完成排序。

**示例：**

```text
输入： [5, 2, 3, 1]
输出： [1, 2, 3, 5]

输入： [5, 1, 1, 2, 0, 0]
输出： [0, 0, 1, 1, 2, 5]
```

算法返回一个新列表，原列表保持不变。数组长度为0或1时，结果与输入元素顺序相同。

## 题目分析

### 将排序问题拆成更小的排序问题

直接对整个数组反复寻找最小值并放到前面，可能需要多轮扫描。合并排序使用分治思想：先把数组分成左右两段，分别排好序，再把两个有序段合并成一个有序数组。

例如 `[5, 2, 3, 1]` 先分成 `[5, 2]` 和 `[3, 1]`，再继续对半拆分，直到每段只剩一个元素。单个元素天然有序，因此递归可以从长度为1的子数组开始返回。

### 定义函数、边界与递推关系

定义 `merge_sort(nums)`：返回 `nums` 中所有元素按非递减顺序排列的新列表。这里的“非递减”允许相邻元素相等。

- **边界条件：** 长度不超过1时，直接返回列表副本。空列表和单元素列表都已经有序。
- **拆分步骤：** 取 `mid = len(nums) // 2`，将数组切成左半段和右半段。
- **递归步骤：** 分别递归排序左右两段。
- **合并步骤：** 从左右有序列表的当前位置开始比较，较小者加入结果；一侧耗尽后，把另一侧剩余元素依次加入。

若数组长度为 $n$，左右两段长度分别约为 $n/2$，合并最多处理 $n$ 个元素，因此递推式为：

$$
T(n)=T(\lfloor n/2\rfloor)+T(\lceil n/2\rceil)+O(n),\qquad T(0),T(1)=O(1).
$$

每次拆分都会让子问题规模约减半；每一层递归的合并与复制总共处理 $O(n)$ 个元素。递归层数为 $O(\log n)$，所以总时间复杂度为 $O(n\log n)$。

### 合并为什么能得到有序结果

合并时，左右两段各自已经有序，因此尚未处理的元素中，左段当前元素是左段最小值，右段当前元素是右段最小值。每次取两者较小者，就是所有尚未处理元素中的最小值。重复这一操作，结果便按升序排列。若两者相等，先取左侧元素可保持相等元素的相对先后顺序，这称为**稳定排序**。

## 实现代码

```python
def merge_sort(nums):
    """返回 nums 的升序副本，不修改原列表。"""
    if len(nums) <= 1:
        return nums.copy()

    mid = len(nums) // 2
    left = merge_sort(nums[:mid])
    right = merge_sort(nums[mid:])

    return merge(left, right)


def merge(left, right):
    """将两个已升序排列的列表合并为一个升序列表。"""
    result = []
    i = j = 0

    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1

    # 每次只会有一侧还剩元素；extend 将其全部接到结果末尾。
    result.extend(left[i:])
    result.extend(right[j:])
    return result


nums = [5, 2, 3, 1]
sorted_nums = merge_sort(nums)
print("排序结果：", sorted_nums)
print("原数组：", nums)
```

输出：

```text
排序结果： [1, 2, 3, 5]
原数组： [5, 2, 3, 1]
```

`merge` 的前提是输入的 `left` 和 `right` 已经分别升序排列；`merge_sort` 负责通过递归保证这个前提。代码使用索引向前移动，不使用 `pop(0)` 删除列表首元素，避免每次删除都搬移后续元素。

## 算法执行过程

以 `nums = [5, 2, 3, 1]` 为例，递归先一路拆分到单元素列表，再按返回顺序合并。

### 递归调用：不断拆分

```text
merge_sort([5, 2, 3, 1])
├── merge_sort([5, 2])
│   ├── merge_sort([5])  → [5]
│   └── merge_sort([2])  → [2]
│   合并 [5] 与 [2]      → [2, 5]
└── merge_sort([3, 1])
    ├── merge_sort([3])  → [3]
    └── merge_sort([1])  → [1]
    合并 [3] 与 [1]      → [1, 3]

合并 [2, 5] 与 [1, 3]    → [1, 2, 3, 5]
```

拆分过程中每层处理的是原问题的一段；递归到长度1时停止。合并从最深层开始，先得到有序短数组，再逐层构造更长的有序数组。

### 递归返回：逐步合并

| 合并的左右有序段 | 依次比较并取出的元素 | 合并结果 |
| --- | --- | --- |
| `[5]` 与 `[2]` | 2、5 | `[2, 5]` |
| `[3]` 与 `[1]` | 1、3 | `[1, 3]` |
| `[2, 5]` 与 `[1, 3]` | 1、2、3，最后接上5 | `[1, 2, 3, 5]` |

最后一次合并的比较过程是：先比较2和1，取1；再比较2和3，取2；再比较5和3，取3。右段已经耗尽，把左段剩下的5接到末尾。此时每个加入结果的元素都不大于尚未处理的元素。

若输入为 `[4, 2, 2, 1]`，在合并两个相等元素时，`left[i] <= right[j]` 会先取左段元素。左右两段原有的相对次序都被保留，因此整个算法稳定。

## 复杂度分析

按元素比较、复制和写入次数计数，假设一次列表索引、比较或追加操作耗时为常数。令 $n$ 为输入元素个数。

### 时间复杂度

数组大致每次对半拆分，形成 $O(\log n)$ 层。每层的所有合并与切片处理合计至多涉及 $O(n)$ 个元素，因此总时间复杂度为 $O(n\log n)$。这一数量级与输入原本是否有序无关，因为代码始终执行相同的拆分和合并流程。

### 辅助空间复杂度

合并时需要结果列表保存元素，额外列表空间峰值为 $O(n)$。切片会复制子列表；递归调用期间各层暂存的切片和合并结果总量仍为线性级。递归栈深度为 $O(\log n)$，因此总辅助空间为 $O(n)$，其中主要开销是合并所需的列表，不是调用栈。

该实现返回新列表，不会修改输入。虽然一些原地归并实现可以改变空间使用方式，但它们需要更复杂的索引与数据搬移；本题代码优先清楚展示分治和合并过程。

## 易错点

| 易错点 | 正确理解 |
| --- | --- |
| 只拆分，不合并 | 拆分只产生小问题；必须在递归返回时合并左右有序结果 |
| 认为长度为1还要继续拆分 | 单元素列表已经有序，是递归终止条件 |
| 合并时只比较一次 | 每取出一个元素都要移动相应一侧的索引，直到某一侧耗尽 |
| 忘记接上剩余元素 | 一侧耗尽后，另一侧的剩余部分仍需加入结果 |
| 相等时先取右边元素 | 用 `<=` 先取左边，才能保证稳定性 |
| 使用 `pop(0)` 取列表首项 | 首项删除会搬移后续元素，反复删除可能使合并步骤退化；使用索引即可 |
| 把每层的 $O(n)$ 误认为总时间也是 $O(n)$ | 共有 $O(\log n)$ 层，每层总工作量为 $O(n)$，总计 $O(n\log n)$ |
| 误认为递归栈是 $O(n)$ | 子数组规模每层约减半，最大递归深度为 $O(\log n)$；总辅助空间 $O(n)$ 来自列表存储 |

## 课堂练习

1. 手动对 `[8, 3, 6, 2]` 画出拆分过程，并按递归返回顺序写出每次合并的结果。
2. 合并 `[1, 4, 7]` 和 `[2, 4, 6]` 时，依次比较并取出的元素是什么？最终结果是什么？
3. 为什么归并时使用 `left[i] <= right[j]` 可以保证稳定？如果改为 `<`，会有什么变化？
4. 若每层合并总共处理 $n$ 个元素，递归共有约 $\log_2 n$ 层，推导总时间复杂度。
5. 如果在合并循环中用 `left.pop(0)` 取元素，为什么不能再直接把单次合并视为线性时间？

::: details 参考答案
1. 拆分为 `[8, 3]` 和 `[6, 2]`，再拆成 `[8]`、`[3]`、`[6]`、`[2]`。依次合并得到 `[3, 8]`、`[2, 6]`，最后合并为 `[2, 3, 6, 8]`。
2. 比较后依次取出1、2、4（左侧）、4（右侧）、6，最后接上7；结果为 `[1, 2, 4, 4, 6, 7]`。
3. 两侧元素相等时先取左侧，保留它们进入当前子数组之前的相对顺序。改为 `<` 后相等时会先取右侧，因此不能保证稳定；排序数值仍然正确。
4. 每层 $O(n)$，共 $O(\log n)$ 层，所以 $T(n)=O(n\log n)$。
5. Python 列表从开头删除元素时，需要把后续元素向前移动，单次可能花费线性时间。若反复删除，长度为 $m$ 的一次合并最坏可累计 $O(m^2)$ 移动；用索引让每个元素只读取、追加一次，合并才是 $O(m)$。
:::
