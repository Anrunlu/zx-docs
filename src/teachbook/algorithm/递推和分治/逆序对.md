# 逆序对

## 题目描述

猫猫 TOM 和小老鼠 JERRY 比赛统计一个序列中的逆序对。给定长度为 $n$ 的正整数序列 $a$，如果两个位置满足 $i<j$ 且 $a_i>a_j$，那么位置对 $(i,j)$ 就是一个**逆序对**。求整个序列中逆序对的总数。

逆序对按元素的**位置**区分，不是按数值去重；数值相等不构成逆序对。例如 `[2, 2, 1]` 中，第1个2和1、第2个2和1分别构成一个逆序对，总数为2。

### 输入、输出与约束

- 输入第一行是元素个数 $n$，第二行是 $n$ 个正整数；使用空格分隔，程序也能读取换行分隔的元素。
- 输出一个整数，表示原序列中的逆序对总数。
- $1\leq n\leq5\times10^5$，每个元素不超过 $10^9$，序列中可以有重复值。

题意中的位置从1开始，Python 列表下标从0开始；两种编号都要满足“前面的元素严格大于后面的元素”。函数 `count_inversions(nums)` 返回“有序新列表、原列表的逆序对数”，原列表保持不变；提交题目时只输出计数。有序列表用于支持后续合并。

函数还支持空列表、单元素列表和负整数：空列表与单元素列表返回的计数都是0，负数按通常的大小关系比较。这些是函数的边界与扩展，不改变上述题目输入范围。

**示例一：与合并排序使用同一组数据。**

```text
输入：
4
5 2 3 1

输出：
5
```

逆序对的位置分别为 $(1,2)$、$(1,3)$、$(1,4)$、$(2,4)$、$(3,4)$，对应数值为 `(5, 2)`、`(5, 3)`、`(5, 1)`、`(2, 1)`、`(3, 1)`。

**示例二：** 输入序列 `[5, 4, 2, 6, 3, 1]`，输出11。它保留了原文中的例子，可以用于核对较长序列的结果。

## 题目分析

### 从逐对检查到合并排序

最直接的方法是对每个位置 $i$，逐个检查后面的所有位置 $j$。共有 $n(n-1)/2$ 个候选位置对，时间复杂度为 $O(n^2)$；在题目给定的规模下，需要减少逐对检查。

[合并排序](./合并排序.md)会先分别排好左右两段，再用两个索引合并。逆序对可以沿用这一分治结构，在合并时利用“左右两段已经有序”的条件批量计数。

| 对照项 | 合并排序 | 逆序对计数 |
| --- | --- | --- |
| 拆分方式 | 按中点拆成左右两段 | 相同 |
| 子调用返回值 | 有序新列表 | 有序新列表和该段的逆序对数 |
| 合并时取左侧 | `left[i] <= right[j]` 时取左 | 相同，不新增逆序对 |
| 合并时取右侧 | `left[i] > right[j]` 时取右 | 同时增加 `len(left) - i` |
| 当前层结果 | 合并后的有序列表 | 有序列表，以及左段、右段、跨段计数之和 |

因此，排序是当前算法的计算手段：每一层既得到有序子列表，也得到这段原始数据中的逆序对数。完整的排序基础见合并排序文档，这里重点分析新增的计数逻辑。

### 将逆序对分成三类

取 `mid = len(nums) // 2`，把当前列表按**原来的位置区间**分成 `nums[:mid]` 和 `nums[mid:]`。一个逆序对只能属于以下一类：

1. 两个元素都在左段，交给左侧递归调用统计。
2. 两个元素都在右段，交给右侧递归调用统计。
3. 前一个元素在左段，后一个元素在右段，在本次合并中统计。

不会出现“前一个元素在右段、后一个元素在左段”的逆序对，因为这不满足原始位置上的先后关系。三类互不重叠，并且覆盖当前段内的所有逆序对。

定义 `count_inversions(nums)` 返回 `(sorted_nums, total)`，其中 `sorted_nums` 是 `nums` 的有序副本，`total` 是 `nums` 原顺序中的逆序对数。设左段、右段的计数为 $I_L,I_R$，本次合并的跨段计数为 $I_C$，则：

$$
I(\text{nums})=I_L+I_R+I_C.
$$

当长度不超过1时，没有两个不同位置可组成逆序对，因此返回 `(nums.copy(), 0)`。对于更长的列表，两个子问题都严格变短，递归最终会到达这一边界。

### 为什么一次增加左段剩余长度

合并时，`i`、`j` 分别指向左右有序段的第一个尚未合并的元素。

如果 `left[i] > right[j]`，左段已经有序，所以：

$$
\text{left}[i],\text{left}[i+1],\ldots,\text{left}[-1]
\quad\text{都大于}\quad\text{right}[j].
$$

这些元素一共有 `len(left) - i` 个；它们在原序列中都来自左侧位置区间，而 `right[j]` 来自右侧位置区间。因此，当前右侧元素与左侧的全部剩余元素各构成一个跨段逆序对。将 `right[j]` 加入合并结果时，一次累计这些配对，再让 `j` 加1。

例如左段为 `[2, 5]`、右段为 `[1, 3]`：比较2和1时，2和5都大于1，一次增加2；随后比较5和3时，再增加1。本次合并的跨段逆序对数为3。

如果 `left[i] <= right[j]`，右段剩余元素都不小于 `right[j]`，也就不小于 `left[i]`。当前左侧元素不能与右段剩余元素构成逆序对，取左侧且不增加计数。**必须用 `<=` 处理取左分支，避免把相等元素误计为逆序对。**

### 为什么排序后仍能统计原来的逆序对

每层划分后，左段所有元素在原序列中的位置都早于右段所有元素。子调用只改变各自段内的排列，不改变元素属于左段还是右段，所以跨段计数依然满足原始位置的先后关系；段内原有的逆序对已经由子调用统计并返回。

本次合并中，每个右侧元素只被取出一次，每次累计的都是左侧尚未取出的、严格较大的元素。已经取出的左侧元素不大于当前右侧元素，不应再次计数。这样跨段逆序对恰好统计一次。

边界计数为0；假设左右子调用的计数和排序都正确，本次合并又正确统计跨段逆序对，三者相加便得到当前段的正确答案。这就同时保证了排序和计数的正确性。

## 实现代码

### Python 归并计数实现

下面的程序可以独立运行，从标准输入读取题目数据，只输出逆序对总数。函数结构与合并排序文档对应：在原来的递归与双指针合并中加入计数及返回值。

```python
import sys


def count_inversions(nums):
    """返回 (有序新列表, 原列表的逆序对数)，不修改 nums。"""
    if len(nums) <= 1:
        return nums.copy(), 0

    mid = len(nums) // 2
    left, left_count = count_inversions(nums[:mid])
    right, right_count = count_inversions(nums[mid:])

    merged, cross_count = merge_and_count(left, right)
    total = left_count + right_count + cross_count
    return merged, total


def merge_and_count(left, right):
    """合并两个有序段，同时统计从左段到右段的逆序对。"""
    result = []
    cross_count = 0
    i = j = 0

    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            # left[i:] 都大于当前 right[j]，批量计数。
            cross_count += len(left) - i
            j += 1

    # 剩余元素接到结果末尾，不再新增跨段逆序对。
    result.extend(left[i:])
    result.extend(right[j:])
    return result, cross_count


def solve():
    values = iter(map(int, sys.stdin.buffer.read().split()))
    n = next(values, None)
    if n is None:
        return

    nums = [next(values) for _ in range(n)]
    del values  # 读取完成，释放输入解析器所保留的缓冲数据。
    _, total = count_inversions(nums)
    print(total)


if __name__ == "__main__":
    solve()
```

用题目示例一运行，输出：

```text
5
```

函数也可以单独调用，例如 `count_inversions([5, 2, 3, 1])` 返回 `([1, 2, 3, 5], 5)`。

| 传入列表 | 返回的有序列表 | 返回的逆序对数 |
| --- | --- | ---: |
| `[]` | `[]` | 0 |
| `[7]` | `[7]` | 0 |
| `[2, 2, 1]` | `[1, 2, 2]` | 2 |
| `[1, 2, 3, 4]` | `[1, 2, 3, 4]` | 0 |
| `[4, 3, 2, 1]` | `[1, 2, 3, 4]` | 6 |
| `[3, -1, 2, -1, 0]` | `[-1, -1, 0, 2, 3]` | 6 |
| `[5, 4, 2, 6, 3, 1]` | `[1, 2, 3, 4, 5, 6]` | 11 |

`merge_and_count` 的输入必须是两个已经有序的列表；它只返回本次合并的跨段计数。`count_inversions` 负责加上左右段内部的计数。代码没有保存每个逆序对，也没有修改原列表。

## 算法执行过程

### 交互动画

动画默认使用 `[5, 2, 3, 1]`，可自动播放、暂停、单步、重置或切换示例，课堂展示时可全屏查看。原数组卡片保持位置固定，动画沿递归合并顺序比较元素，并将找到的逆序对收集到右侧。输入框最多接受10个整数，留空可以观察空列表边界。

卡片的“位置”从0开始，对应 Python 列表下标；题目中的第1个位置对应动画位置0。收集卡片同时显示数值与原位置，用来区分重复值组成的不同配对。配对始终满足前位置小于后位置、前值严格大于后值；相等时取左侧，不增加计数。

当右段当前元素更小时，动画一次收集它与左段全部剩余元素的配对，并显示本次新增的 `len(left) - i`。例如顶层合并取出1时，一次收集 `(2, 1)` 和 `(5, 1)`，增加2。“已收集”统计整个演示中累计找到的逆序对，“逐对核对目标”是对这个小序列预先逐对检查得到的总数；当前合并的跨段计数仍需与左右子调用计数区分，见下方过程表。

### 递归调用与返回：与合并排序对照

沿用合并排序的输入 `[5, 2, 3, 1]`。调用顺序仍然是先完成左分支，再完成右分支，最后合并；现在每个子调用会返回“有序列表、逆序对数”两个结果。

```text
count_inversions([5, 2, 3, 1])
├── count_inversions([5, 2])
│   ├── count_inversions([5]) → ([5], 0)
│   └── count_inversions([2]) → ([2], 0)
│   合并 [5] 与 [2]：新增1 → ([2, 5], 1)
└── count_inversions([3, 1])
    ├── count_inversions([3]) → ([3], 0)
    └── count_inversions([1]) → ([1], 0)
    合并 [3] 与 [1]：新增1 → ([1, 3], 1)

合并 [2, 5] 与 [1, 3]：跨段新增3
总数 = 左段1 + 右段1 + 跨段3 = 5
返回 ([1, 2, 3, 5], 5)
```

左段内部统计的是 `(5, 2)`，右段内部统计的是 `(3, 1)`。顶层合并再统计 `(2, 1)`、`(5, 1)`、`(5, 3)`，正好覆盖题目描述中的5个逆序对。

### 双指针合并：逐步累计跨段逆序对

顶层合并中，`left = [2, 5]`、`right = [1, 3]`，初始 `i = j = 0`、`cross_count = 0`。表中的索引均为本步开始时的状态。

| 步骤 | 开始的 `i`、`j` | 比较或操作 | 本步新增的配对 | 新增数量 | 累计跨段计数 | 本步后的 `result` |
| --- | --- | --- | --- | ---: | ---: | --- |
| 1 | 0、0 | `2 > 1`，取右侧1 | `(2, 1)`、`(5, 1)` | `2 - 0 = 2` | 2 | `[1]` |
| 2 | 0、1 | `2 <= 3`，取左侧2 | 无 | 0 | 2 | `[1, 2]` |
| 3 | 1、1 | `5 > 3`，取右侧3 | `(5, 3)` | `2 - 1 = 1` | 3 | `[1, 2, 3]` |
| 4 | 1、2 | 右侧耗尽，接上左侧剩余的5 | 无 | 0 | 3 | `[1, 2, 3, 5]` |

最后得到的3只是**跨段计数**；加上两个子调用各自的1，才得到整个列表的答案5。合并排序中的双指针操作没有改变，新增的是取右分支中的批量计数。

一侧耗尽后的追加操作不新增配对：右侧耗尽时，相关逆序对已经在取出右侧元素时统计；左侧耗尽时，没有尚未处理的左侧元素可以与右侧剩余元素配对。

可先查看[合并排序的交互动画](./合并排序.md#交互动画)，观察左右段的取出顺序，再用本节表格核对每一步新增的逆序对数。

### 重复值：相等时不计数

输入 `[2, 2, 1]`，第一层分成 `[2]` 和 `[2, 1]`。右侧子调用先统计一个 `(2, 1)`，返回 `([1, 2], 1)`。

顶层合并 `[2]` 与 `[1, 2]` 时，先比较2和1，新增1个跨段逆序对；接着比较2和2，相等时取左侧，不新增逆序对。最终总数为 `0 + 1 + 1 = 2`。这两个 `(2, 1)` 来自不同的位置，不能按数值去重。

## 复杂度分析

按元素比较、计数加法、索引和复制次数计费，假设一次整数比较与加法为常数时间，`append` 按摊还常数时间计算；切片与 `extend` 按涉及的元素个数计费。令 $n$ 为输入长度，以下结论针对 $n\geq2$；空列表与单元素列表直接返回，耗时和额外空间均为常数级。

### 时间复杂度

两个子问题长度分别为 $\lfloor n/2\rfloor$、$\lceil n/2\rceil$。合并与复制处理 $O(n)$ 个元素，而新增的计数语句每次只做一次加法，所以运行时间满足：

$$
T(n)=T(\lfloor n/2\rfloor)+T(\lceil n/2\rceil)+O(n).
$$

与合并排序相同，每层总工作量为 $O(n)$，共有 $O(\log n)$ 层，时间复杂度为 $O(n\log n)$。本实现始终拆分并合并所有元素，最好、平均与最坏情况下的时间均为 $\Theta(n\log n)$；即使逆序对数为0，也不会直接跳过这些步骤。

批量增加 `len(left) - i` 不需要遍历这些配对。逆序对可能多达 $n(n-1)/2$ 个，算法通过累加数量来统计，因此计数可以在 $O(n\log n)$ 时间内完成；如果要求逐个输出全部逆序对，仅输出就可能需要 $\Theta(n^2)$ 时间。这是不同的任务。

### 辅助空间复杂度

切片、子调用返回的有序列表和合并结果同时存活的空间峰值为 $O(n)$，递归调用栈深度为 $O(\log n)$，所以总辅助空间为 $O(n)$。与合并排序一样，不能把整个执行期间每次分配的列表长度累加后当作空间峰值。

每层只增加固定数量的计数变量，因此新增的计数逻辑不改变总体空间复杂度。读取题目数据也需要线性空间；程序只输出一个计数，没有存储全部逆序对。

当 $n=5\times10^5$ 且序列严格递减时，逆序对数为124999750000，超过32位有符号整数范围。Python 整数可以精确保存这一结果；换用固定宽度整数的语言时，计数应使用足够大的整数类型，例如 C++ 的 `long long`。

## 易错点

| 易错点 | 正确理解 |
| --- | --- |
| 只比较数值大小，忽略位置先后 | 逆序对同时要求原位置 $i<j$ 和数值 $a_i>a_j$ |
| 把相等元素也算作逆序对 | 取左分支使用 `<=`，只有严格大于时才计数 |
| 取右侧元素时只增加1 | 左段剩余元素全部大于当前右侧元素，应增加 `len(left) - i` |
| 使用左段总长度或 `len(left) - i - 1` | 只统计尚未合并的元素，并包含当前 `left[i]` |
| 将跨段计数当作当前段总数 | 当前段答案是左段计数、右段计数、跨段计数之和 |
| 相同数值的配对只计一次 | 配对由位置区分，重复值可能产生多个不同逆序对 |
| 先把整个原数组排好序，再统计 | 会丢失原顺序；必须在分治合并过程中统计 |
| 把两个无序列表直接交给 `merge_and_count` | 批量计数依赖左右两段分别有序，由递归保证 |
| 在接上剩余元素时再增加计数 | 对应配对已经统计或不存在，再加会重复计数 |
| 使用 `pop(0)` 反复删除列表首项 | 首项删除会移动后续元素；使用索引保持合并为线性时间 |
| 用32位整数保存较大规模答案 | 最大计数为 $n(n-1)/2$，可能超过32位范围 |

1. 对 `[8, 3, 6, 2]` 写出第一层左右段的逆序对数、顶层合并的跨段计数和最终答案。
2. 合并有序左段 `[1, 4, 7]` 与右段 `[2, 4, 6]` 时，共有多少个跨段逆序对？列出取右侧元素时每次新增的数量。
3. `[2, 2, 1]` 的逆序对数是多少？如果把取左条件从 `<=` 改为 `<`，程序会错误得到多少？
4. 长度为5的严格递减序列共有多少个逆序对？长度为 $n$ 时的最大值如何表示？
5. 将当前算法与合并排序比较：需要保留哪些步骤，新增哪些返回值和操作？为什么复杂度不变？
6. 对 `[1, 2, 3, 4]`，答案为0，为什么本实现仍需 $\Theta(n\log n)$ 时间？

::: details 参考答案
1. 左段 `[8, 3]` 计数1，右段 `[6, 2]` 计数1。顶层合并 `[3, 8]` 与 `[2, 6]`：取2时新增2，取6时新增1，跨段计数3。最终为 `1 + 1 + 3 = 5`。
2. 共4个。取2时，左段剩余的4、7都大于2，新增2；相等的4先取左侧，不计数；取右侧4时剩余7，新增1；取6时剩余7，新增1。总数为 `2 + 1 + 1 = 4`。
3. 正确答案为2。改为 `<` 后，顶层比较2和2时会误走取右分支，多加1，错误得到3。
4. 共有 $5\times4/2=10$ 个。严格递减时每个前后位置对都满足条件，最大计数为 $n(n-1)/2$；全相等或非递减序列的计数为0。
5. 保留中点拆分、左右递归排序、双指针合并和追加剩余元素。子调用新增逆序对计数返回值，取右分支增加左段剩余长度，当前层将三类计数相加。每次批量计数只增加常数时间，时间仍为 $O(n\log n)$、辅助空间仍为 $O(n)$。
6. 该实现没有有序输入提前返回的优化，仍会完成所有递归拆分、切片复制与合并。答案为0不代表求解过程没有工作量。
