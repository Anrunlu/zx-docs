# 01背包问题

<Badge text="基础" type="tip" /> <Badge text="01背包" type="tip" /> <Badge text="Python" type="tip" />

**背包容量只有5，四件物品不能全部装下，怎样挑选才能获得最大价值？** 每件物品只有“选”和“不选”两种决策；先按物品划分阶段，再比较同一容量下的最优结果。

::: tip 本节学习目标
- **会建模：** 用“前i件物品、容量上限j”定义状态，明确容量不必用满。
- **会推导：** 从选或不选当前物品得到二维递推，说明为什么两种选择都读取上一行。
- **会压缩：** 将二维表压缩为一维数组，解释容量倒序如何保证每件物品最多使用一次。

前置知识：列表、二维列表与 `max`；可对照[硬币找零问题](./硬币找零问题.md)和[完全背包问题](./完全背包问题.md)，比较有限选择与无限使用。
:::

## 题目描述

有N件物品和一个容量为V的背包。第i件物品的体积为 $v_i$，价值为 $w_i$。每件物品只能选取一次，也可以不选。

选择其中一些物品，使总体积**不超过**V，并让总价值最大，输出这个最大价值。

“01”表示每件物品的选取次数只能是0或1。即使两件物品体积、价值完全相同，它们仍是两件独立物品，可以各选一次。

### 输入、输出与编号规则

| 项目 | 约定 |
| --- | --- |
| 第一行 | 两个整数N、V，分别表示物品数量与背包容量 |
| 后续N行 | 每行两个整数vᵢ、wᵢ，表示一件物品的体积与价值 |
| 输出 | 在总体积不超过V的条件下，可以获得的最大总价值 |
| 数据范围 | $1\leq N,V\leq1000$，$1\leq v_i,w_i\leq1000$ |
| 选取规则 | 每件最多一次；允许一件不选，不要求装满 |
| 编号 | 物品从1到N编号；Python中第i件对应 `items[i - 1]` |

程序只需输出最大价值，不要求恢复物品编号或统计最优方案条数。主函数另允许空物品列表或容量0，用于核对边界，两种情况都返回0；原题输入范围仍以上表为准。

交互动画另提供“恢复一种最优物品组合”的教学扩展：使用完整二维表从后向前检查选择，按1开始的编号展示物品、最大价值及已用体积；多个方案等值时，优先不选当前物品。Python主实现仍只返回最大价值，不增加方案输出要求。

### 贯穿示例

**输入：**

```text
4 5
1 2
2 4
3 4
4 5
```

**输出：**

```text
8
```

| 物品编号 | 体积 | 价值 |
| ---: | ---: | ---: |
| 1 | 1 | 2 |
| 2 | 2 | 4 |
| 3 | 3 | 4 |
| 4 | 4 | 5 |

选择第2、3件，总体积为 $2+3=5$，总价值为 $4+4=8$。选择第1、4件虽然也恰好装满，但价值只有 $2+5=7$。

不一定所有题例都能装满。例如只有一件体积3、价值5的物品，容量为4时，最大价值为5，允许留下1单位空余容量。

## 题目分析

### 从枚举子集到按物品分阶段

每件物品选或不选，直接枚举全部子集共有 $2^N$ 种选择。不同选择经常留下同一个子问题：“只考虑前几件物品，在给定容量上限下，最多能得到多少价值？”可以保存这些子问题的答案，避免重复计算。

贪心选择也不能代替整体比较。例如容量4，物品为 `(体积3,价值5)`、`(体积2,价值3)`、`(体积2,价值3)`。按单位体积价值优先会先选第一件，得到5；选后两件却能得到6。

用数量变量表示，每件物品对应 $x_i\in\{0,1\}$，需要求：

$$
\max\sum_{i=1}^{N}w_ix_i,
\qquad\text{满足}\quad
\sum_{i=1}^{N}v_ix_i\leq V.
$$

### 定义二维状态与边界

定义 `f[i][j]`：**只考虑前i件物品，总体积不超过j时，能够取得的最大价值。**

- i表示已经考虑的物品数量，不要求必须选择第i件。
- j是容量上限，不是已经使用的体积。
- 状态值是最大总价值，不是方案数，也不是剩余容量。

边界为：

$$
f[0][j]=0\quad(0\leq j\leq V),\qquad
f[i][0]=0\quad(0\leq i\leq N).
$$

没有物品时只能不选；容量为0时，因为所有物品体积为正，也只能不选。

所有状态初始化为0是合法的：无论容量上限是多少，“不选任何物品”都是一种价值为0的可行方案。这与硬币找零中“恰好凑出指定金额”的不可达初始化不同。

### 根据当前物品选或不选推导转移

第i件物品的体积、价值分别为 $v_i,w_i$。计算 `f[i][j]` 时：

| 选择 | 所需条件 | 当前候选价值 |
| --- | --- | --- |
| 不选第i件 | 始终允许 | $f[i-1][j]$ |
| 选择第i件 | $j\geq v_i$ | $f[i-1][j-v_i]+w_i$ |

于是：

$$
f[i][j]=
\begin{cases}
f[i-1][j], & j<v_i,\\
\max\bigl(f[i-1][j],\ f[i-1][j-v_i]+w_i\bigr), & j\geq v_i.
\end{cases}
$$

**两种选择都从上一行读取。** 选择第i件后，剩下的容量只能交给前i−1件物品，不能把第i件再选一次。

这里的 `j - v_i` 是为当前物品预留体积后，留给其他物品的容量上限；不用知道某条历史方案实际剩余了多少空间。

### 为什么只保留最大价值就足够

任意合法方案，要么不含第i件，要么包含第i件，两类覆盖全部情况。

不选时，决策全部落在前i−1件内；选时，去掉第i件，剩下的物品必定属于前i−1件，且总体积不超过j−vᵢ。

如果剩余选择不是该容量上限下的最优方案，就可以替换成更优的前缀方案，仍不超容量，且不会与当前物品重复。因此分别取两类的最优值再比较，就得到当前状态的最优值。

边界正确，按物品逐行计算，依赖的上一行都已求出，最终 `f[N][V]` 正确。

### 一维压缩：为什么容量必须倒序

当前行只依赖上一行，可以用 `dp[j]` 原地保存结果。处理第i件物品之前，dp表示 `f[i - 1]`；本轮完成后，表示 `f[i]`。

更新规则为：

$$
dp[j]\leftarrow\max\bigl(dp[j],\ dp[j-v_i]+w_i\bigr).
$$

原地更新时，必须让j从V递减到vᵢ。因为vᵢ>0，j−vᵢ小于j，那个位置本轮还没更新，读取的仍是上一行结果，保证当前物品最多使用一次。

例如只有一件体积2、价值3的物品，容量4：

| 更新方向 | 容量2与4的计算 | 得到的结果 |
| --- | --- | --- |
| 倒序 | 先算dp[4]时，dp[2]仍为0；之后才算dp[2] | 最大价值3，只选一次 |
| 正序 | 先把dp[2]更新为3，再用它把dp[4]更新为6 | 错误地使用当前物品两次 |

::: tip 倒序的前提是“一维原地更新”
二维实现读取独立的上一行，因此容量正序或倒序都可以。一维原地实现必须倒序，是为了保留上一行数据；不能脱离存储方式，只背诵循环方向。
:::

### 与完全背包、硬币找零的关系

| 问题 | 每件或每种的限制 | 核心转移含义 |
| --- | --- | --- |
| 本题：01背包 | 每件最多一次 | 选当前物品后，只能接前i−1件的结果 |
| 完全背包 | 每种可以无限使用 | 选当前物品后，仍可接包含当前种类的结果 |
| 硬币找零 | 每种面额无限使用，要求恰好凑出 | 保存最少枚数，比较候选时取min |

完全背包的一维写法通常按物品在外、容量正序在内，让同一种物品可以继续追加。本题的倒序更新正是为了阻止这种重复使用。

## 实现代码

### Python 一维倒序实现

`knapsack_01(items, capacity)` 接收 `(体积, 价值)` 元组列表与容量上限，返回最大价值，不修改输入。主实现按原题标准输入格式读取数据，可完整复制运行。

```python
import sys


def knapsack_01(items, capacity):
    """每件物品最多选一次，返回容量上限内的最大价值。"""
    dp = [0] * (capacity + 1)

    for volume, value in items:
        for j in range(capacity, volume - 1, -1):
            dp[j] = max(dp[j], dp[j - volume] + value)

    return dp[capacity]


def main():
    data = list(map(int, sys.stdin.buffer.read().split()))
    n, capacity = data[0], data[1]
    items = [
        (data[2 + 2 * i], data[3 + 2 * i])
        for i in range(n)
    ]
    print(knapsack_01(items, capacity))


if __name__ == "__main__":
    main()
```

输入贯穿示例后，**运行输出：**

```text
8
```

| 关键代码 | 对应含义 |
| --- | --- |
| `dp = [0] * (capacity + 1)` | 各容量上限下都允许先不选物品 |
| `for volume, value in items` | 每次只引入一件新物品 |
| `range(capacity, volume - 1, -1)` | 容量倒序，并包含恰好能装入该物品的容量volume |
| `dp[j - volume] + value` | 使用前面物品的旧状态，再选择当前物品一次 |
| `max(dp[j], ...)` | 在不选与选择当前物品之间取较大价值 |
| `return dp[capacity]` | 返回容量上限内的最优值，不要求实际用满 |

若物品体积超过capacity，内层循环为空，这件物品自然被跳过。

### Python 二维教学实现

::: details 补充实现：保留完整状态表，直接对应递推式

二维写法适合用小规模数据核对每一行，内存占用高于主实现。以下函数可以单独运行，输出与主实现一致。

```python
def knapsack_01_table(items, capacity):
    n = len(items)
    f = [[0] * (capacity + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        volume, value = items[i - 1]
        for j in range(capacity + 1):
            f[i][j] = f[i - 1][j]
            if volume <= j:
                f[i][j] = max(
                    f[i][j],
                    f[i - 1][j - volume] + value,
                )

    return f[n][capacity]


print(knapsack_01_table([(1, 2), (2, 4), (3, 4), (4, 5)], 5))
```

**运行输出：**

```text
8
```

各行需要独立创建，不能写成 `[[0] * (capacity + 1)] * (n + 1)`，否则所有行会引用同一个列表，破坏上一行与当前行的区别。
:::

### 主示例的完整状态表

使用物品 `[(1,2), (2,4), (3,4), (4,5)]`，容量上限5。每行表示“允许考虑前几件物品”，每列表示容量上限，不表示必须使用的体积。

| 已考虑的物品 | 容量0 | 容量1 | 容量2 | 容量3 | 容量4 | 容量5 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 0件 | 0 | 0 | 0 | 0 | 0 | 0 |
| 第1件：(1,2) | 0 | 2 | 2 | 2 | 2 | 2 |
| 前2件，新增(2,4) | 0 | 2 | 4 | 6 | 6 | 6 |
| 前3件，新增(3,4) | 0 | 2 | 4 | 6 | 6 | **8** |
| 前4件，新增(4,5) | 0 | 2 | 4 | 6 | 6 | **8** |

`f[1][5] = 2`并不表示把第一件物品装了5次，而是容量5也只能选择这件一次，价值为2，剩余空间不用满。

### 第3件怎样把答案从6提高到8

处理体积3、价值4的第3件时，容量5对应两种选择：

$$
f[3][5]=\max\bigl(f[2][5],\ f[2][2]+4\bigr)
=\max(6,4+4)=8.
$$

不选第3件时，前两件最多取得6；选第3件时，给前两件留下容量2，最优是选第2件得到4，再加当前价值4，总价值为8。

引入第4件后：

$$
f[4][5]=\max\bigl(f[3][5],\ f[3][1]+5\bigr)
=\max(8,2+5)=8.
$$

所以最优方案不一定包含最后一件物品，最大价值保持8。

### 一维更新对应同一张表

处理第2件 `(2,4)` 前，一维数组为 `[0, 2, 2, 2, 2, 2]`：

| 倒序容量j | 原dp[j] | 尚未更新的dp[j−2] | 当前物品价值 | 新dp[j] |
| ---: | ---: | ---: | ---: | ---: |
| 5 | 2 | 2 | 4 | 6 |
| 4 | 2 | 2 | 4 | 6 |
| 3 | 2 | 2 | 4 | 6 |
| 2 | 2 | 0 | 4 | 4 |

本轮结束后，数组为 `[0, 2, 4, 6, 6, 6]`，恰好对应二维表的第2行。每轮一维更新都复现一行，最终得到同一个答案。

## 复杂度分析

设物品数量为N，容量上限为V，按整数加法、比较和数组访问为常数时间计：

| 实现 | 时间复杂度 | 辅助空间复杂度 |
| --- | --- | --- |
| 一维倒序主实现 | $O((N+1)(V+1))$，原题范围内通常写为 $O(NV)$ | $O(V+1)$，通常写为 $O(V)$ |
| 二维教学实现 | $O((N+1)(V+1))$，通常写为 $O(NV)$ | $O((N+1)(V+1))$，通常写为 $O(NV)$ |

主实现初始化V+1个状态，物品i实际更新 $\max(0,V-v_i+1)$ 个位置。在原题范围内，最多进行约100万次状态更新。

这里的辅助空间不包含输入物品列表；主程序还需保存输入数据，占 $O(N)$ 空间。两种实现都不枚举全部子集，也不使用递归栈。

动画为展示过程额外保留二维表，并用它恢复一种最优组合，所需表空间为 $O(NV)$；回溯本身最多检查N件物品。动画的二维展示、日志与方案输出不能作为一维主实现需要同样空间的依据。

算法工作量依赖容量的数值V，而不只是V的二进制位数，因此属于伪多项式时间算法。

## 易错点

| 常见错误 | 正确理解与修正 |
| --- | --- |
| 将j理解为实际已经装入的体积 | 本文j表示容量上限，可以留有空余 |
| 将“最大价值”改成“最大体积” | 体积用于判断约束，比较的是价值之和 |
| 选当前物品时从二维当前行读取 | 01背包必须读取上一行，避免再次选择当前物品 |
| 一维原地更新时容量正序 | 会利用本轮新状态，重复使用当前物品 |
| 认为二维容量也必须倒序 | 二维读取独立上一行，正序或倒序都可以 |
| 使用 `range(capacity, volume, -1)` | 会漏掉容量恰好等于volume，右端应为volume−1 |
| 物品放得下就直接覆盖为选择它 | 放得下不代表选择它更好，必须与不选时的价值比较 |
| 把相同体积、价值的两件物品合并为一件 | 它们是独立物品，可以各选一次，不能随意去重 |
| 对本题使用“正容量不可达”的初始化 | 本题不要求装满，不选物品对所有容量上限都合法 |
| 把全0初始化直接用于“恰好装满”变式 | 恰好模型中除0体积外的初始状态应不可达，否则会误判 |

## 课堂练习

### 基础核对

计算下列最大价值。元组统一表示 `(体积, 价值)`。

| items | capacity |
| --- | ---: |
| `[(1,2), (2,4), (3,4), (4,5)]` | 5 |
| `[(2,3)]` | 4 |
| `[(3,5)]` | 4 |
| `[(5,10)]` | 4 |
| `[(2,3), (2,3)]` | 4 |
| `[]`（函数边界扩展） | 5 |
| `[(1,2)]` | 0（函数边界扩展） |

::: details 参考答案
依次为 **8、3、5、0、6、0、0**。

只有一件 `(2,3)` 时，即使容量为4也只能获得3；两件独立的 `(2,3)` 则可以各选一次，获得6。物品体积超过容量时只能不选，空列表或容量0都返回0。
:::

### 过程推演

容量为4，物品依次为 `[(1,2), (3,5), (2,3)]`：

1. 写出每件物品处理完成后的一维dp数组。
2. 展开计算加入第3件后容量4的两个候选。
3. 给出一组最优物品编号。

::: details 参考答案

| 阶段 | dp[0]到dp[4] |
| --- | --- |
| 初始化 | `[0, 0, 0, 0, 0]` |
| 处理第1件后 | `[0, 2, 2, 2, 2]` |
| 处理第2件后 | `[0, 2, 2, 5, 7]` |
| 处理第3件后 | `[0, 2, 3, 5, 7]` |

处理第3件时，容量4的候选是：不选得7；选择它则使用上一轮容量2的价值2，再加3，得到5。因此仍取7。

最优选择为第1、2件，总体积1+3=4，总价值2+5=7。

### 进阶思考

1. 只有物品 `(2,3)`、容量4时，把一维容量循环改为正序，数组会怎样变化？错误在哪里？
2. 如果要求“恰好装满”，只有物品 `(3,5)`、容量4时，是否仍能输出5？应怎样改变状态初始化与转移？
3. 对主示例，如果每种物品都允许无限使用，最大价值是多少？这与本题结果有什么区别？

::: details 参考答案

1. 初始化 `[0,0,0,0,0]`。正序更新容量2后为 `[0,0,3,0,0]`，容量3后为 `[0,0,3,3,0]`，容量4后为 `[0,0,3,3,6]`。最后读到了本轮已经更新的dp[2]，把唯一的物品选了两次。
2. 不能，体积3无法恰好填满容量4。此时应定义“恰好使用体积j的最大价值”，只令dp[0]=0，其余状态初始不可达（如负无穷）；仍按物品、容量倒序更新，并只从可达来源扩展。最终若dp[4]仍不可达，应报告无解，不能把留下空余容量的价值5当成答案。
3. 最大价值为10。例如体积1、价值2的物品选5件，或体积2、价值4的物品选2件再选一件体积1的物品。本题这些重复选取不合法，01背包的答案为8；两者的区别来自使用次数限制，而非容量或价值变化。
:::
