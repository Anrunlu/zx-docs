# 零钱兑换

<Badge text="中等" type="tip" /> <Badge text="完全背包计数" type="tip" /> <Badge text="Python" type="tip" />

**面额为 `[1, 2, 5]`，凑出金额5有4种组合。为什么 `2 + 2 + 1` 和 `1 + 2 + 2` 只能算同一种？** 把“按什么顺序拿硬币”改为“每种面额各拿几枚”，就能找到不重不漏的计数方法。

::: tip 本节学习目标
- **会建模：** 用面额种类和目标金额定义组合计数，区分组合数、排列数与最少硬币数。
- **会转移：** 按是否使用当前面额分类，理解无限使用为何依赖当前行的较小金额。
- **会核对：** 说明面额在外、金额正序的原因，检查金额0、无解与空面额列表。

前置知识：列表、循环和动态规划状态；可先阅读[摆花](./摆花.md)，对比“每类数量有限”与“每类数量无限”的计数。
:::

## 题目描述

给定互不相同的正整数面额列表 `coins`，以及非负整数总金额 `amount`。每种面额的硬币数量无限，求**恰好凑出该金额的不同硬币组合数**。

组合只按每种面额使用的枚数区分，不考虑拿取或排列顺序。若无法凑出目标金额，返回0。

本文沿用[课程原页面](https://docs.z-xin.net/teachbook/algorithm/动态规划/零钱兑换.html)的组合计数题意。题目保证最终答案符合32位有符号整数范围；输出精确计数，不取模。

### 参数、结果与边界约定

| 项目 | 约定 |
| --- | --- |
| 输入面额 | `coins`，元素为互不相同的正整数，面额不要求有序 |
| 输入金额 | `amount`，非负整数 |
| 返回值 | 恰好凑出amount的组合数；无解返回0 |
| 使用次数 | 每种面额可以使用0枚、1枚或更多枚 |
| 金额为0 | 返回1，对应不使用任何硬币的空组合 |
| 空面额列表 | 金额为0返回1；金额为正数返回0 |
| 输入有效性 | 主实现按上述约定接收有效参数，不修改输入列表 |

将面额依输入顺序记为 $c_1,c_2,\ldots,c_n$。第 $i$ 种面额对应 Python 中的 `coins[i - 1]`。列表顺序只用于分阶段计数，不表示硬币必须按这个顺序支付。

空列表约定用于补全函数边界。零面额、负面额、小数或重复面额不属于本文有效输入；例如重复的两个1元面额不能当成两种独立硬币计数。

### 贯穿示例

```text
输入： amount = 5, coins = [1, 2, 5]
输出： 4
```

| 每种面额的枚数（1元、2元、5元） | 对应组合 |
| --- | --- |
| $(5,0,0)$ | $1+1+1+1+1$ |
| $(3,1,0)$ | $1+1+1+2$ |
| $(1,2,0)$ | $1+2+2$ |
| $(0,0,1)$ | $5$ |

例如 `2 + 2 + 1` 与 `1 + 2 + 2` 都对应 $(1,2,0)$，只计一次。

::: warning 先明确所求的量
本题求组合数。相同输入若问“最少使用几枚硬币”，答案会是1，因为一枚5元即可；若问“拿取顺序不同也算不同”，又是另一种计数。三种问题的状态含义和转移不能混用。
:::

## 题目分析

### 把组合表示为数量向量

给每种面额确定一个使用次数 $x_i$，组合就确定了。需要统计非负整数解的个数：

$$
c_1x_1+c_2x_2+\cdots+c_nx_n=amount,\qquad x_i\geq0.
$$

只要始终按面额种类作决策，就不会因为同一批硬币的排列不同而重复计数。

直接枚举各个 $x_i$ 可以求解，但会反复遇到相同子问题：“只使用前几种面额，恰好凑出某个金额，有多少种组合？”动态规划保存这些中间计数供后续复用。

### 先定义二维状态与边界

定义 $f[i][j]$：**只使用前 $i$ 种面额，恰好凑出金额 $j$ 的组合数。**

- $i$ 表示可用种类数，不要求每种都使用。
- $j$ 是恰好的目标金额，不是最多可以支付的金额。
- 状态值是组合数，不是使用的硬币枚数。

没有任何面额时：

$$
f[0][0]=1,\qquad f[0][j]=0\quad(j>0).
$$

对任意 $i$，都有 $f[i][0]=1$。因为面额均为正数，凑出0只能所有面额都选0枚，空组合唯一。

### 按当前面额是否出现分类

计算 $f[i][j]$，当前面额为 $c_i$。所有组合可以分成互不重叠的两类：

| 当前面额的使用情况 | 对应子问题 | 组合数 |
| --- | --- | --- |
| 一枚也不使用 | 只用前i−1种面额凑出j | $f[i-1][j]$ |
| 至少使用一枚，且 $j\geq c_i$ | 去掉一枚当前硬币后，用前i种面额凑出j−cᵢ | $f[i][j-c_i]$ |

第二类仍允许使用当前面额，所以读取的是**当前行**，不是上一行。由此得到：

$$
f[i][j]=
\begin{cases}
f[i-1][j], & 0\leq j<c_i,\\
f[i-1][j]+f[i][j-c_i], & j\geq c_i.
\end{cases}
$$

这里“去掉一枚”只是建立两个组合集合之间的对应关系。同一面额的硬币不区分个体，不会因为可以去掉其中任意一枚而产生额外计数。

::: tip 正确性依据：分类互斥，且对应唯一
不含当前面额与含有当前面额覆盖了全部组合，两类互不重叠。对第二类，去掉一枚当前面额，与较小金额的组合一一对应；反过来，给每个子组合加回这一枚，就得到唯一的当前组合。因此两类计数相加，既不漏算，也不重算。
:::

按i从小到大、j从小到大计算，上一行及当前行依赖的较小金额都已求出。结合边界，可以逐行证明最终的 $f[n][amount]$ 正确。

### 压缩为一维数组

当前状态只需上一行同列与当前行较小金额，可以复用一个数组：

```text
dp[0] = 1，其余为0
依次处理每个面额coin：
    金额j从coin递增到amount：
        dp[j] += dp[j - coin]
```

处理当前面额前，数组保存上一阶段的计数。更新某个j时：

- `dp[j]` 尚未更新，表示不使用当前面额的组合数，即 $f[i-1][j]$。
- 因为面额为正数，`j - coin < j`；该位置已经具有当前阶段的含义，表示 $f[i][j-coin]$，允许继续使用当前面额。
- 两者相加后，`dp[j]` 变成 $f[i][j]$。

小于当前面额的金额不会用到它，保留旧值即可。处理完全部面额后，`dp[amount]` 就是答案。

### 为什么两层循环不能随意交换

**面额在外：控制可用的种类集合。** 每一种组合只在这个固定阶段顺序中被构造，不按硬币拿取顺序反复构造。例如 `[1, 2]` 凑3时，组合 `1 + 2` 只在处理面额2时计入一次。

**金额正序：允许重复使用当前面额。** 例如只有面额2、目标4时，先得到 `dp[2] = 1`，再用它更新 `dp[4] = 1`，对应使用两枚2元。

若把金额放在外层，对每个金额再枚举所有面额，通常是在按“最后一枚硬币”累加有序序列。`[1, 2]` 凑3会得到 `1+1+1`、`1+2`、`2+1` 共3种，而本题只有2种组合。

若在面额外层将金额改为倒序，则本轮无法复用当前面额刚产生的计数，会变成每种面额至多使用一次的模型。循环顺序是状态含义的一部分。

## 实现代码

### Python 一维动态规划

`change(amount, coins)` 返回精确组合数。下面的程序可以完整复制运行，第一组对应贯穿示例，最后一组核对原页面分析中提到的金额11。

```python
def change(amount, coins):
    """每种正整数面额无限使用，返回恰好凑出 amount 的组合数。"""
    dp = [0] * (amount + 1)
    dp[0] = 1

    for coin in coins:
        for j in range(coin, amount + 1):
            dp[j] += dp[j - coin]

    return dp[amount]


if __name__ == "__main__":
    cases = [
        (5, [1, 2, 5]),
        (3, [2]),
        (10, [10]),
        (0, [1, 2, 5]),
        (0, []),
        (7, []),
        (11, [1, 2, 5]),
    ]
    for amount, coins in cases:
        print(f"amount={amount}, coins={coins} -> {change(amount, coins)}")
```

**运行输出：**

```text
amount=5, coins=[1, 2, 5] -> 4
amount=3, coins=[2] -> 0
amount=10, coins=[10] -> 1
amount=0, coins=[1, 2, 5] -> 1
amount=0, coins=[] -> 1
amount=7, coins=[] -> 0
amount=11, coins=[1, 2, 5] -> 11
```

| 关键代码 | 对应含义 |
| --- | --- |
| `dp[0] = 1` | 唯一空组合，为后续计数提供起点 |
| `for coin in coins` | 逐步增加可使用的面额种类 |
| `range(coin, amount + 1)` | 金额递增，包含目标金额，允许重复使用当前面额 |
| `dp[j] += dp[j - coin]` | 保留不使用当前面额的组合，再加入至少使用一枚的组合 |
| `return dp[amount]` | 返回精确金额的计数；不可达状态自然保持0 |

面额超过目标时，对应的内层循环为空，不会访问负下标。程序不需要排序；改变互异面额的输入顺序不改变最终组合数。代码也不需要在无解时另外返回−1，本题约定的无解计数就是0。

## 算法执行过程

### 按面额观察状态变化

以 `amount = 5`、`coins = [1, 2, 5]` 为例。表中每一行对应一轮外层循环后的完整数组，列表示恰好的金额。

| 已处理的面额 | 金额0 | 金额1 | 金额2 | 金额3 | 金额4 | 金额5 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 尚无面额 | 1 | 0 | 0 | 0 | 0 | 0 |
| 只用1元 | 1 | 1 | 1 | 1 | 1 | 1 |
| 允许1元、2元 | 1 | 1 | 2 | 2 | 3 | 3 |
| 允许1元、2元、5元 | 1 | 1 | 2 | 2 | 3 | **4** |

只使用1元时，每个金额只有一种组合。加入2元后，金额5的3种组合为：5枚1元、3枚1元与1枚2元、1枚1元与2枚2元。最后加入5元，又增加“一枚5元”这一种组合。

### 跟踪面额2这一轮

进入本轮前，`dp = [1, 1, 1, 1, 1, 1]`。按j递增更新：

| 当前金额j | 尚未更新的dp[j] | 当前阶段的dp[j−2] | 更新后dp[j] |
| ---: | ---: | ---: | ---: |
| 2 | 1 | `dp[0] = 1` | 2 |
| 3 | 1 | `dp[1] = 1` | 2 |
| 4 | 1 | `dp[2] = 2`，本轮已更新 | 3 |
| 5 | 1 | `dp[3] = 2`，本轮已更新 | 3 |

在j=4时，`dp[2]` 已包括“两元一枚”的组合，给它再加一枚2元，就得到“两元两枚”。这正是无限使用当前面额的来源。

接下来处理5元，仅需更新j=5：

$$
dp[5]\leftarrow dp[5]+dp[0]=3+1=4.
$$

`dp[0]` 对应的空组合加上一枚5元，恰好得到新增组合。最终答案与题目中列举的四个数量向量一致。

### 核对金额11的计数

沿用原页面分析中的 `coins = [1, 2, 5]`、`amount = 11`，按5元枚数分类，可独立核对程序结果：

| 5元枚数 | 剩余金额 | 2元可用枚数 | 组合数 |
| ---: | ---: | --- | ---: |
| 0 | 11 | 0到5 | 6 |
| 1 | 6 | 0到3 | 4 |
| 2 | 1 | 只能为0 | 1 |

每次确定5元和2元枚数后，1元枚数被唯一确定，所以共有 $6+4+1=11$ 种组合。

## 复杂度分析

设面额种类数为 $n$，目标金额为 $A=amount$。在整数加法与数组访问按常数时间计的常见模型下：

| 项目 | 复杂度 | 依据 |
| --- | --- | --- |
| 时间 | $O\bigl((n+1)(A+1)\bigr)$；当n、A均为正时通常简写为 $O(nA)$ | 初始化A+1个状态，每种面额扫描至多A个金额 |
| 辅助空间 | $O(A+1)$ | 仅保存长度为A+1的dp数组，无递归栈 |

实际状态更新次数为：

$$
\sum_{i=1}^{n}\max(0,A-c_i+1).
$$

上述包含初始化的复杂度表达也适用于空列表或金额0。若保留完整二维状态表，时间仍为 $O(nA)$（n、A为正），辅助空间则为 $O((n+1)(A+1))$。

题目保证最终答案在32位有符号整数范围内，但这不保证每个较小金额的中间计数也都在同一范围内。Python 整数可以自动扩展；若计数使用B位表示，一次加法的位运算成本最多为 $O(B)$，不能在严格位复杂度模型中始终视为常数。

本题不枚举或存储全部组合，只统计其数量；组合总数很大时，也不会因此逐个生成方案。

## 易错点

| 常见错误 | 正确理解与修正 |
| --- | --- |
| 把答案理解为最少硬币数 | 本题统计组合数；转移用加法，不用 `min` |
| 将dp[0]初始化为0 | 空组合应计1种，否则所有状态都无法产生计数 |
| 把金额放在外层、面额放在内层 | 会把不同拿取顺序计为不同序列，偏离组合计数 |
| 每个面额下倒序遍历金额 | 无法重复使用当前面额，变成每种至多使用一次 |
| 遍历到amount之前就结束 | `range`右端不包含，必须写 `amount + 1` |
| 用同一面额的重复条目作两类硬币 | 会重复统计；本文要求面额互异 |
| 接受0或负面额而不调整模型 | 正面额保证金额依赖严格变小；零面额甚至会产生无限种枚数组合 |
| 无解时返回−1 | 无解表示有0种组合，返回0 |
| 沿用摆花的模数 | 本题要求精确计数，不取模 |
| 认为最终答案小，就可忽略中间计数溢出 | 较小金额的计数可能更大；Python主实现使用任意精度整数 |

## 课堂练习

### 基础核对

计算下列参数的返回值：

| amount | coins |
| ---: | --- |
| 5 | `[1, 2, 5]` |
| 3 | `[2]` |
| 4 | `[2]` |
| 0 | `[2, 5]` |
| 0 | `[]` |
| 7 | `[]` |
| 5 | `[5, 1, 2]` |

::: details 参考答案
依次为 **4、0、1、1、1、0、4**。

面额2无法凑出奇数3，但可以用两枚凑出4；金额0的空组合有且只有一种。面额输入顺序不同不会改变组合集合，因此最后一项仍为4。
:::

### 过程推演

给定 `amount = 6`、`coins = [2, 3]`：

1. 写出初始化、处理2元后、处理3元后的dp数组。
2. 展开本轮j=6时的更新，指出其中哪个值来自当前阶段。
3. 列出所有组合，与最终计数核对。

::: details 参考答案

| 阶段 | dp[0]到dp[6] |
| --- | --- |
| 初始化 | `[1, 0, 0, 0, 0, 0, 0]` |
| 处理2元后 | `[1, 0, 1, 0, 1, 0, 1]` |
| 处理3元后 | `[1, 0, 1, 1, 1, 1, 2]` |

处理3元、j=6时，旧的 `dp[6] = 1` 对应三枚2元；`dp[3] = 1` 是本轮j=3时得到的计数，对应一枚3元。更新为 `dp[6] = 1 + 1 = 2`。

两种组合为 $2+2+2$ 和 $3+3$。读取本轮的 `dp[3]`，才能生成含有两枚3元的组合。
:::

### 进阶思考

1. `[1, 2]` 凑金额3，如果交换两层循环，会得到多少？列出多计的情况。
2. `[2]` 凑金额4，如果改为金额倒序，结果是什么？为什么？
3. 与[摆花](./摆花.md)相比，为什么本题可直接使用当前行的较小金额，而摆花需要检查每类数量上限？

::: details 参考答案

1. 得到3，计入 `1+1+1`、`1+2`、`2+1`。后两项在本题中属于同一组合，所以正确组合数为2。
2. 得到0。先处理j=4时，`dp[2]` 仍为0；之后即使j=2更新为1，也不会返回更新j=4。它只允许使用一枚2元，无法凑出4。
3. 本题每种面额无限可用，给较小金额的任意合法组合加一枚当前面额仍然合法。摆花的每类数量有上限，直接反复追加可能超限，所以其基础转移需要枚举当前类的合法数量，并从上一类的状态读取。两题都按种类控制组合计数，但可重复选择的条件不同。
:::
