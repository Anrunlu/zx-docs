# 矩阵连乘

<Badge text="中等" type="tip" /> <Badge text="区间DP" type="tip" /> <Badge text="Python" type="tip" />

**同样三个矩阵相乘，只改括号位置，乘法次数为什么会从 4500 变成 27000？**

::: tip 本节学习目标
- **会建模：** 说明为什么 $dp[i][j]$ 必须用一对下标，并写出状态转移方程。
- **会追踪：** 按区间长度填出 dp 表与分割点表，还原最优括号方案。
- **会核对：** 解释递推顺序的必要性，验证合并代价下标与复杂度。

前置知识：重叠子问题与复用子解，可参见[快速幂](../递推和分治/二分法求幂.md)；线性 DP 见[使用最小花费爬楼梯](./使用最小花费爬楼梯.md)；本课讲义见[2026年秋第7次课](../2026年秋第7次课.md)。
:::

## 题目描述

给定 $n$ 个矩阵 $A_1,A_2,\dots,A_n$，其中 $A_i$ 与 $A_{i+1}$ 可乘。由于矩阵乘法满足结合律，可以用加括号的方式改变计算次序。不同次序的**标量乘法次数**差别很大。

用数组 $p$ 给出维数：$A_i$ 的形状是 $p_{i-1}\times p_i$，因此 $p$ 的长度为 $n+1$。一个 $a\times b$ 矩阵乘一个 $b\times c$ 矩阵，需要 $abc$ 次标量乘法，结果为 $a\times c$。

要求：求最少标量乘法次数，并输出对应的完全加括号方案。

输入为矩阵个数 $n$ 与 $n+1$ 个维数；输出为最少次数、dp 表、分割点表与最优括号方案。约定 $2\leq n$，$p_i\geq1$。

### 贯穿示例

全文共用 4 个矩阵的示例：

```text
p = [10, 30, 5, 60, 20]
A1: 10x30, A2: 30x5, A3: 5x60, A4: 60x20
正确输出：最少 8500 次，括号方案 ((A1A2)(A3A4))
```

先用 3 个矩阵 $p=[10,30,5,60]$ 建立直观：

| 括号方案 | 第一步 | 第二步 | 标量乘法总数 |
| --- | --- | --- | ---: |
| $((A_1A_2)A_3)$ | $10\cdot30\cdot5=1500$，得 $10\times5$ | $10\cdot5\cdot60=3000$ | 4500 |
| $(A_1(A_2A_3))$ | $30\cdot5\cdot60=9000$，得 $30\times60$ | $10\cdot30\cdot60=18000$ | 27000 |

同样的结果矩阵，代价相差 6 倍。**括号次序不改变乘积，只改变工作量。**

## 题目分析

### 从题意到方法

$n$ 个矩阵的完全加括号方案数是第 $n-1$ 个 Catalan 数，$n=10$ 时已有 4862 种，$n=20$ 时超过 17 亿，逐个枚举不可行。

关键在于：无论中间怎么加括号，计算 $A_i\cdots A_j$ 的**最后一次乘法**一定发生在某个分割点 $k$ 处，先分别算出 $A_i\cdots A_k$ 与 $A_{k+1}\cdots A_j$，再把两个结果相乘。前半部分结果是 $p_{i-1}\times p_k$，后半部分是 $p_k\times p_j$，这次相乘需要 $p_{i-1}p_kp_j$ 次标量乘法。

::: tip 核心结论
定义 $dp[i][j]$ 为计算 $A_i\cdots A_j$ 的最少标量乘法次数，则

$$
dp[i][j]=\min_{i\leq k<j}\Bigl(dp[i][k]+dp[k+1][j]+p_{i-1}p_kp_j\Bigr),\qquad dp[i][i]=0,
$$

答案为 $dp[1][n]$。合并代价的三个下标分别取自**整个区间的左端、分割点、右端**，不能改用子区间的局部端点。
:::

### 定义任务与处理边界

- 单个矩阵不需要乘法，故 $dp[i][i]=0$；其余状态初值应设为无穷大（或 `None`），不能设 0，否则 `min` 永远取到 0。
- 分割点范围是 $i\leq k<j$：左子区间至少含 $A_i$，右子区间至少含 $A_j$，$k=j$ 不是合法分割。
- 计算 $dp[i][j]$ 时要用到 $dp[i][k]$ 与 $dp[k+1][j]$，两者都是**更短**的区间，所以必须按区间长度 $L=2,3,\dots,n$ 从小到大推进，同长度内再枚举左端点 $i$。

若按左端点 $i$ 从 1 到 $n$ 递增再枚举 $j$，计算 $dp[1][4]$ 时会用到 $dp[3][4]$，而它的左端点更大、尚未计算。这是区间 DP 与线性 DP 在计算顺序上的本质差别。

### 递归不等于动态规划

按上式直接写递归，每个子区间会在不同分割方案中被反复求解，时间仍是 Catalan 级（指数级）。旧版实现正是这种写法：**能算出正确值，但没有把重叠子问题压下来**。只有记忆化递归或自底向上填表，让每个 $O(n^2)$ 个子区间只算一次，才得到 $O(n^3)$。这与[快速幂](../递推和分治/二分法求幂.md)中「同一个半次幂只求一次」是同一个道理。

### 为什么结果正确

对区间长度 $L$ 归纳。$L=1$ 时 $dp[i][i]=0$，成立。设所有长度小于 $L$ 的区间已取到最优值。任一计算 $A_i\cdots A_j$ 的方案，最后一次乘法必在某个 $k$ 处，其前两部分各自是子区间 $A_i\cdots A_k$、$A_{k+1}\cdots A_j$ 的一种计算次序，费用不低于对应的 $dp$ 值；最后一步费用固定为 $p_{i-1}p_kp_j$。因此任何方案的费用不低于上式右端，而取到最小值的 $k$ 对应的方案确实可行，等号成立。$L=n$、$i=1$、$j=n$ 即得全局最优。

### 输出括号方案

只求最少次数时，dp 表就够了。若还要输出方案，在每次**严格更优**时把 $k$ 记入决策表 $s[i][j]$，再从 $s[1][n]$ 递归打印：区间 $[i,j]$ 的最优方案是 $([i,s[i][j]]\,[s[i][j]+1,j])$，单点区间输出 $A_i$。

## 实现代码

### Python 主实现

```python
def matrix_chain_order(p):
    """p[i-1] x p[i] 是 A_i 的形状，矩阵按 1..n 编号。"""
    n = len(p) - 1
    dp = [[0] * (n + 1) for _ in range(n + 1)]
    split = [[0] * (n + 1) for _ in range(n + 1)]
    for length in range(2, n + 1):
        for i in range(1, n - length + 2):
            j = i + length - 1
            best = None
            for k in range(i, j):
                cost = dp[i][k] + dp[k + 1][j] + p[i - 1] * p[k] * p[j]
                if best is None or cost < best:
                    best = cost
                    split[i][j] = k
            dp[i][j] = best
    return dp, split


def parenthesization(split, i, j):
    if i == j:
        return f"A{i}"
    k = split[i][j]
    return f"({parenthesization(split, i, k)}{parenthesization(split, k + 1, j)})"


if __name__ == "__main__":
    examples = [
        [10, 30, 5, 60],
        [10, 30, 5, 60, 20],
    ]
    for p in examples:
        dp, split = matrix_chain_order(p)
        n = len(p) - 1
        print(p, "-> 最少乘法次数:", dp[1][n],
              "| 括号:", parenthesization(split, 1, n))
    p = examples[1]
    dp, split = matrix_chain_order(p)
    print("dp 上三角:")
    for i in range(1, len(p)):
        print([dp[i][j] for j in range(i, len(p))])
    print("split 上三角:")
    for i in range(1, len(p)):
        print([split[i][j] for j in range(i, len(p))])
```

运行输出：

```text
[10, 30, 5, 60] -> 最少乘法次数: 4500 | 括号: ((A1A2)A3)
[10, 30, 5, 60, 20] -> 最少乘法次数: 8500 | 括号: ((A1A2)(A3A4))
dp 上三角:
[0, 1500, 4500, 8500]
[0, 9000, 9000]
[0, 6000]
[0]
split 上三角:
[0, 1, 2, 2]
[0, 2, 2]
[0, 3]
[0]
```

`best = None` 等价于把非对角状态初始化为无穷大；`split[i][j]` 只在严格更小时更新，因此并列最优时保留先遇到的分割点。

### 对照：朴素递归（不记忆化）

```python
def naive(p, i, j):
    if i == j:
        return 0
    return min(naive(p, i, k) + naive(p, k + 1, j)
               + p[i - 1] * p[k] * p[j]
               for k in range(i, j))
```

这段代码形式上写出了同一个转移式，答案也正确，但同一区间被重复求解，规模稍大即不可用。**它是对照组，不是本题的主实现。**

## 算法执行过程

对贯穿示例 $p=[10,30,5,60,20]$ 按长度填表：

| 长度 | 区间 | 候选 k 的计算 | 最优值 | 分割点 |
| --- | --- | --- | ---: | ---: |
| 2 | $[1,2]$ | $p_0p_1p_2=10\cdot30\cdot5=1500$ | 1500 | 1 |
| 2 | $[2,3]$ | $p_1p_2p_3=30\cdot5\cdot60=9000$ | 9000 | 2 |
| 2 | $[3,4]$ | $p_2p_3p_4=5\cdot60\cdot20=6000$ | 6000 | 3 |
| 3 | $[1,3]$ | k=1: $0+9000+10\cdot30\cdot60=27000$；k=2: $1500+0+10\cdot5\cdot60=4500$ | 4500 | 2 |
| 3 | $[2,4]$ | k=2: $0+6000+30\cdot5\cdot20=9000$；k=3: $9000+0+30\cdot60\cdot20=45000$ | 9000 | 2 |
| 4 | $[1,4]$ | k=1: $0+9000+10\cdot30\cdot20=15000$；k=2: $1500+6000+10\cdot5\cdot20=8500$；k=3: $4500+0+10\cdot60\cdot20=16500$ | **8500** | 2 |

最终 dp 表（只列上三角，行表示左端点 $i$）：

| i \ j | 1 | 2 | 3 | 4 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 0 | 1500 | 4500 | 8500 |
| 2 | | 0 | 9000 | 9000 |
| 3 | | | 0 | 6000 |
| 4 | | | | 0 |

由 $s[1][4]=2$、$s[1][2]=1$、$s[3][4]=3$ 回溯，得到 $((A_1A_2)(A_3A_4))$：左侧花 1500、右侧花 6000，两个结果 $10\times5$ 与 $5\times20$ 相乘花 $10\cdot5\cdot20=1000$，合计 8500。

胜出的是「平衡分割」k=2，而不是让某一步单独最省的 k=1；这说明最优值必须比较全部候选分割点，不能凭直觉选一个。

## 复杂度分析

### 先看结论

| 实现或任务 | 时间复杂度 | 辅助空间复杂度 | 计数模型 |
| --- | --- | --- | --- |
| 自底向上填表 | $O(n^3)$ | $O(n^2)$ | 一次标量乘、加、比较为常数时间 |
| 记忆化递归 | $O(n^3)$ | $O(n^2)$，另有 $O(n)$ 栈 | 同上 |
| 朴素递归（不记忆化） | Catalan 级，指数增长 | $O(n)$ 栈 | 同上 |
| 输出最优括号方案 | $O(n)$ | 复用 $O(n^2)$ 决策表 | 输出长度为 $O(n)$ |

区间 $[i,j]$ 共有 $n(n+1)/2=O(n^2)$ 个状态，每个状态枚举至多 $n-1$ 个分割点、每次做常数次运算，故时间为 $O(n^3)$；dp 表与决策表各占 $O(n^2)$。

这里的 $n$ 是**矩阵个数**，统计对象是**标量乘法次数**，不是程序实际运行时间。实际耗时还受矩阵元素规模、内存访问与实现语言影响；维数很大时整数位数成本也不能忽略。若只求最少次数、不输出括号方案，可以省略 `split` 表，但空间量级仍是 $O(n^2)$。

## 易错点

| 错误想法或写法 | 反例或后果 | 正确处理 |
| --- | --- | --- |
| 分割点写成 `range(i, j+1)` | `k=j` 时右子区间为空，访问 `dp[j+1][j]` | 用 `range(i, j)`，即 $i\leq k<j$ |
| 合并代价写成 $p_i p_k p_j$ | $dp[1][3]$ 的 k=2 会由 4500 错算成 10500 | 写 $p_{i-1}p_kp_j$，下标取整个区间的两端 |
| 把代价写成子区间局部维数 | 与区间 $[i,j]$ 不对应，答案偏小 | 结果矩阵形状由 $p_{i-1}$、$p_k$、$p_j$ 决定 |
| 按左端点 i 递增、再枚举 j 递推 | $dp[1][4]$ 会读到未算的 $dp[3][4]$ | 外层按长度 $L$ 递增 |
| 非对角状态初值设为 0 | `min` 永远取 0，答案错误 | 用无穷大或 `None` |
| 认为写成递归就是动态规划 | 无记忆化时仍是指数级 | 必须记忆化或自底向上填表 |
| `split` 在代价相等时也更新 | 输出方案改变，不唯一 | 只在严格更小时更新，并说明并列情形 |
| 把 $p$ 的长度当作 $n$ | 维数下标越界 | $p$ 有 $n+1$ 个元素，$A_i$ 为 $p_{i-1}\times p_i$ |
| 把"最少乘法次数"当实际运行时间 | 大矩阵实测与次数不成正比 | 明确计数模型 |

## 课堂练习

### 基础核对

**1.** 对 $p=[10,30,5,60]$，写出两种括号方案的代价，并说出 $dp[1][3]$ 与最优分割点。

::: details 参考答案
$((A_1A_2)A_3)$ 为 $1500+3000=4500$；$(A_1(A_2A_3))$ 为 $9000+18000=27000$。故 $dp[1][3]=4500$，最优分割点 $s[1][3]=2$，对应 $((A_1A_2)A_3)$。
:::

**2.** 贯穿示例中 $dp[2][4]$ 等于多少？它用到了哪些更短的区间？

::: details 参考答案
$dp[2][4]=9000$，分割点 $k=2$。计算它用到 $dp[2][2]=0$、$dp[3][4]=6000$ 和代价 $p_1p_2p_4=30\cdot5\cdot20=3000$；候选 k=3 得到 $9000+0+30\cdot60\cdot20=45000$，故取 9000。这两个子区间长度分别是 1 和 2，都小于 3。
:::

### 过程推演

**3.** 列出贯穿示例 $dp[1][4]$ 的三个候选值，并说明最优括号方案如何由决策表恢复。

::: details 参考答案
k=1：$0+dp[2][4]+p_0p_1p_4=9000+6000=15000$；k=2：$dp[1][2]+dp[3][4]+p_0p_2p_4=1500+6000+1000=8500$；k=3：$dp[1][3]+0+p_0p_3p_4=4500+12000=16500$。最小为 8500，$s[1][4]=2$。再由 $s[1][2]=1$、$s[3][4]=3$ 递归打印，得到 $((A_1A_2)(A_3A_4))$。
:::

**4.** 若把填表顺序改成先固定左端点 $i$ 再枚举右端点 $j$，计算 $dp[1][4]$ 时具体会读错哪个状态？

::: details 参考答案
会读到尚未计算的 $dp[3][4]$（以及 k=2 时的 $dp[3][4]$）。它的左端点 3 大于 1，按左端点递增的顺序排在 $dp[1][4]$ 之后才被计算；此时它仍是初值 0 或无穷，导致 8500 被算错。按区间长度递推可保证所有长度小于 4 的区间先算完。
:::

### 进阶思考

**5.** $n=2$ 时 dp 表长什么样？为什么边界是 $dp[i][i]=0$ 而不是 $p_{i-1}p_i$？

::: details 参考答案
只有 $dp[1][2]=p_0p_1p_2$，两个对角元都是 0。单个矩阵已经是最终结果，不需要执行任何矩阵乘法；$p_{i-1}p_i$ 是元素个数，不是乘法次数，不能当作边界。
:::

**6.** 石子合并与矩阵连乘都按区间长度递推，它们的转移有什么不同？

::: details 参考答案
两者状态都是 $dp[i][j]$、都要枚举分割点 $k$、复杂度同为 $O(n^3)/O(n^2)$。差别在合并代价：石子合并的代价是区间内石子总数（可用前缀和 $O(1)$ 求出，只依赖 $i,j$），矩阵连乘的代价是 $p_{i-1}p_kp_j$，**依赖分割点 $k$**。因此矩阵连乘的候选值必须逐个 k 计算，不能把代价提到 `min` 外面。
:::
