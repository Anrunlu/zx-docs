# 使用最小花费爬楼梯

<Badge text="基础" type="tip" /> <Badge text="线性动态规划" type="tip" /> <Badge text="Python" type="tip" />

**费用为 `[10, 15, 20]`，为什么到达楼顶只需花15，而不是先支付10？** 起点可以选，前进可以跨一步或两步；关键是先说清“到哪里”与“已经支付了哪里”。

::: tip 本节学习目标
- **会建模：** 区分收费台阶与楼顶，用“到达位置的最小累计费用”定义状态。
- **会推导：** 从最后一次前进的来源出发，得到边界、转移与最终答案。
- **会核对：** 跟踪状态表和滚动变量，避免混用两种不同的费用状态。

前置知识：列表下标、循环与 `min`；可结合[爬楼梯](./爬楼梯.md)比较计数问题与最小费用问题，结合[打家劫舍](./打家劫舍.md)复习前缀状态。
:::

## 题目描述

给定非负整数列表 `cost`，其中 `cost[i]` 表示从下标为 $i$ 的台阶向上前进时，需要支付的费用。支付一次该台阶的费用后，可以向上前进1阶或2阶。

可以选择从下标0或下标1的台阶开始。求到达楼顶的最小总费用。

题意与两个主要示例参照[课程原页面](https://docs.z-xin.net/teachbook/algorithm/动态规划/使用最小花费爬楼梯.html)。本文只计算最小费用，不要求程序返回具体路径或统计最优路径条数。

### 参数、编号与支付规则

设 `n = len(cost)`，本篇讨论 $n\geq2$，每项费用为非负整数。输入按这些条件保证有效；原页面未给出具体规模上限，本文不额外设定固定的n上限。

| 项目 | 约定 |
| --- | --- |
| 收费台阶 | 下标0到n−1，共n个，均与Python列表下标一致 |
| 楼顶 | 位置n，在最后一个收费台阶之后，不是位置n−1 |
| 起点 | 免费站到位置0或位置1，之后离开该台阶时仍需支付其费用 |
| 每次前进 | 从当前位置向上前进1或2阶 |
| 何时支付 | 离开台阶i时支付cost[i]；跨过而未停留的台阶不支付 |
| 终点 | 到达位置n即结束；楼顶没有对应的cost[n] |
| 返回值 | 到达楼顶的最小总费用，不修改输入列表 |

“免费选择起点”并不意味着起点的费用被免除，而是尚未从起点向上走，暂时不支付。非负费用保证直接选择位置1的初始费用0，不会比先从位置0走到位置1更贵。

### 贯穿示例

```text
输入： cost = [10, 15, 20]
输出： 15
```

这里n=3，收费台阶为0、1、2，楼顶为3。可行路径包括：

| 路径（数字表示位置） | 支付的费用 | 总费用 |
| --- | --- | ---: |
| `1 → 3（楼顶）` | `cost[1]` | **15** |
| `0 → 2 → 3（楼顶）` | `cost[0] + cost[2]` | 30 |
| `0 → 1 → 3（楼顶）` | `cost[0] + cost[1]` | 25 |

从位置1直接跨两阶到楼顶，只支付15。位置2被跨过，所以不支付20。

### 第二个示例

```text
输入： cost = [1, 100, 1, 1, 1, 100, 1, 1, 100, 1]
输出： 6
```

一种最优路径为 `0 → 2 → 4 → 6 → 7 → 9 → 10（楼顶）`。离开的收费台阶依次为0、2、4、6、7、9，每次费用均为1，总费用为6。

## 题目分析

::: tip 核心结论
到达位置i的最后一次前进，只可能来自i−1或i−2。分别取到达来源位置的最小费用，再加上离开该来源台阶的费用，比较两个候选即可。
:::

### 从路径选择到位置状态

直接枚举起点与每一步走1阶或2阶，可以比较全部路径，但会反复求解“到达同一个位置，最少需要花多少钱”。

只在局部选择便宜的台阶也不可靠。例如 `cost = [1, 2, 100]`，虽然位置0的费用更小，从0出发至少要花3，而从1出发可以直接到达楼顶，只花2。

一旦到达同一个位置，接下来可以走哪些步、需要支付哪些费用，与此前具体走过的路径无关。因此，到达该位置的较贵路径可以被较便宜路径替代，只需保存一个最小累计费用。

### 定义状态与起点边界

定义 `dp[i]`：**已经到达位置i，但尚未支付离开位置i的费用时，所需的最小累计费用。**

定义范围为 $0\leq i\leq n$。当i=n时，已经到达楼顶，之后不再支付或前进。

由于可以直接选择位置0或位置1作为起点：

$$
dp[0]=0,\qquad dp[1]=0.
$$

注意，`dp[1] = 0` 表示可以直接站到位置1，不表示从位置0走到位置1不用支付 `cost[0]`。起点有两个选择，不能只初始化其中一个。

### 从最后一次前进推导转移

对于 $2\leq i\leq n$，到达i只可能有两种来源：

| 最后一次前进 | 到达来源的费用 | 本次需要支付 | 候选总费用 |
| --- | --- | --- | --- |
| 从i−1走1阶 | `dp[i - 1]` | `cost[i - 1]` | `dp[i - 1] + cost[i - 1]` |
| 从i−2走2阶 | `dp[i - 2]` | `cost[i - 2]` | `dp[i - 2] + cost[i - 2]` |

于是：

$$
dp[i]=\min\bigl(dp[i-1]+cost[i-1],\ dp[i-2]+cost[i-2]\bigr).
$$

本次支付的是**来源台阶**的费用，不能加 `cost[i]`。尤其当i=n时，列表里根本没有 `cost[n]`。

依次计算i=2到n，最终返回 `dp[n]`。长度为2时也可以直接套用：

$$
dp[2]=\min(cost[1],cost[0]).
$$

所以在本文有效输入范围内，不需要为两个台阶另写一个特殊算法。

### 为什么只保留最小费用就足够

任意一条到达i的路径，最后一步必然来自i−1或i−2，不会有第三种来源。固定来源后，离开该来源的费用已经确定。

如果到达来源的那段路径不是最便宜的，就可以换成到达同一来源的最便宜路径；之后的这一步仍然合法，且总费用不会增加。

因此两个候选分别给出对应来源下的最小费用，取较小值就得到到达i的最小费用。起点边界正确，按位置从小到大递推，每次依赖的状态都已求出，最终 `dp[n]` 正确。

### 两种状态写法要成套使用

另一种常见定义是：`paid[i]` 表示**到达收费台阶i，并且已经支付该阶费用**后的最小累计费用。它也能求解，但初始化、公式、下标范围和返回值都必须与定义一致。

| 对照项目 | 本文的到达状态dp | 已支付当前费用的状态paid |
| --- | --- | --- |
| 定义范围 | 位置0到n，包含楼顶 | 收费台阶0到n−1 |
| 初始值 | `dp[0] = dp[1] = 0` | `paid[0] = cost[0]`，`paid[1] = cost[1]` |
| 递推（i≥2） | `min(dp[i-1]+cost[i-1], dp[i-2]+cost[i-2])` | `min(paid[i-1], paid[i-2]) + cost[i]` |
| 最终答案 | `dp[n]` | `min(paid[n-1], paid[n-2])` |

在非负费用、至少两个台阶的约定下，两种定义都成立；对收费台阶有 `paid[i] = dp[i] + cost[i]`。原页面后半部分把前一种公式标成错误，实际问题在于混用了状态含义，不能据此否定前一种算法。

本文代码与过程表统一使用dp定义，避免在同一推导中切换。

### 从状态表到滚动变量

计算 `dp[i]` 只需要 `dp[i - 2]` 与 `dp[i - 1]`，不再需要更早的状态，因此可以只保存两个变量。

每轮开始时，`prev2` 对应 `dp[i - 2]`，`prev1` 对应 `dp[i - 1]`。先利用旧值求 `current`，再同时推进到下一对状态。这样可以将辅助空间从 $O(n)$ 降到 $O(1)$。

## 实现代码

### Python 状态表实现

`min_cost_climbing_stairs(cost)` 返回到达位置n的最小费用。输入满足题目约定；下面的程序可以完整复制运行。

```python
def min_cost_climbing_stairs(cost):
    """返回到达楼顶的最小费用；cost为长度至少2的非负整数列表。"""
    n = len(cost)
    dp = [0] * (n + 1)  # dp[0]和dp[1]均为0，表示两个可选起点

    for i in range(2, n + 1):
        from_one = dp[i - 1] + cost[i - 1]
        from_two = dp[i - 2] + cost[i - 2]
        dp[i] = min(from_one, from_two)

    return dp[n]


if __name__ == "__main__":
    cases = [
        [10, 15, 20],
        [1, 100, 1, 1, 1, 100, 1, 1, 100, 1],
        [5, 8],
        [0, 0, 0],
        [1, 2, 100],
    ]
    for cost in cases:
        print(f"cost={cost} -> {min_cost_climbing_stairs(cost)}")
```

**运行输出：**

```text
cost=[10, 15, 20] -> 15
cost=[1, 100, 1, 1, 1, 100, 1, 1, 100, 1] -> 6
cost=[5, 8] -> 5
cost=[0, 0, 0] -> 0
cost=[1, 2, 100] -> 2
```

| 关键代码 | 对应含义 |
| --- | --- |
| `dp = [0] * (n + 1)` | 包含楼顶位置n；起点0与1的到达费用均为0 |
| `range(2, n + 1)` | 从第一个非起点状态开始，计算到楼顶为止 |
| `dp[i - 1] + cost[i - 1]` | 从前一个台阶支付费用后走1阶 |
| `dp[i - 2] + cost[i - 2]` | 从前两个台阶支付费用后走2阶 |
| `return dp[n]` | 返回到达楼顶的费用，而非最后一个收费台阶的到达费用 |

### Python 滚动变量实现

::: details 补充实现：只保存相邻两个到达状态

以下函数与主实现使用相同的状态定义、输入约定和返回值，可单独复制调用。

```python
def min_cost_climbing_stairs_rolling(cost):
    """用两个滚动变量计算到达楼顶的最小费用。"""
    prev2, prev1 = 0, 0  # 初始分别对应dp[0]、dp[1]

    for i in range(2, len(cost) + 1):
        current = min(
            prev1 + cost[i - 1],
            prev2 + cost[i - 2],
        )
        prev2, prev1 = prev1, current

    return prev1


print(min_cost_climbing_stairs_rolling([10, 15, 20]))
```

**运行输出：**

```text
15
```

同时赋值的右侧先使用旧值计算。每轮结束后，`prev2` 保存旧的 `dp[i - 1]`，`prev1` 保存新的 `dp[i]`，正好用于下一轮。
:::

## 算法执行过程

### 主示例：楼顶位于3，而不是2

`cost = [10, 15, 20]`，先把位置与费用对齐：

```text
位置：  0       1       2       3（楼顶）
费用： 10      15      20       无
起点： 可选    可选

最优路径：1 ──支付15，前进2阶──> 3（楼顶）
```

状态计算过程为：

| 位置i | 从i−1前进的候选 | 从i−2前进的候选 | dp[i] | 含义 |
| ---: | --- | --- | ---: | --- |
| 0 | — | — | 0 | 可直接选择为起点 |
| 1 | — | — | 0 | 可直接选择为起点 |
| 2 | `dp[1]+cost[1] = 0+15` | `dp[0]+cost[0] = 0+10` | 10 | 到达位置2，尚未支付20 |
| 3 | `dp[2]+cost[2] = 10+20` | `dp[1]+cost[1] = 0+15` | **15** | 已到达楼顶，不再付费 |

因此完整状态表为 `[0, 0, 10, 15]`，答案取最后一个状态15。`dp[2] = 10` 并不是已经完成登顶的费用，不能在这里提前返回。

### 第二个示例：状态值与具体路径核对

对于 `cost = [1, 100, 1, 1, 1, 100, 1, 1, 100, 1]`：

| 位置i | 离开该位置的费用cost[i] | 到达该位置的最小费用dp[i] |
| ---: | ---: | ---: |
| 0 | 1 | 0 |
| 1 | 100 | 0 |
| 2 | 1 | 1 |
| 3 | 1 | 2 |
| 4 | 1 | 2 |
| 5 | 100 | 3 |
| 6 | 1 | 3 |
| 7 | 1 | 4 |
| 8 | 100 | 4 |
| 9 | 1 | 5 |
| 10（楼顶） | 无 | **6** |

表中 `dp[8] = 4` 与 `cost[8] = 100` 不矛盾：到达位置8时还没有支付离开它的费用；最优登顶路径可以从位置7跨到位置9，避免支付位置8的100。

题目描述给出的路径 `0 → 2 → 4 → 6 → 7 → 9 → 10`，费用之和确实为6，与 `dp[10]` 一致。路径仅用于解释结果，主程序不额外存储路径。

### 滚动变量对应同一过程

主示例中，初始 `(prev2, prev1) = (0, 0)`：

| 当前i | 轮前prev2 | 轮前prev1 | 算出的current | 轮后(prev2, prev1) |
| ---: | ---: | ---: | ---: | --- |
| 2 | 0 | 0 | 10 | `(0, 10)` |
| 3 | 0 | 10 | 15 | `(10, 15)` |

最后 `prev1` 保存的是 `dp[3]`，返回15。

## 复杂度分析

设收费台阶数为 $n$，按整数加法、比较与列表访问为常数时间计：

| 实现 | 时间复杂度 | 辅助空间复杂度 | 依据 |
| --- | --- | --- | --- |
| 状态表主实现 | $O(n)$ | $O(n)$ | 分配n+1个状态，计算n−1次转移 |
| 滚动变量实现 | $O(n)$ | $O(1)$ | 同样计算n−1次转移，只保留固定数量变量 |

两种实现都不修改输入，也不使用递归栈。这里的空间分析不计输入列表，且只求最小费用；若要恢复一条最优路径，可以另存每个位置的来源，需要额外 $O(n)$ 空间。

若直接递归而不缓存，相同位置会被反复求解，最坏调用量呈指数增长。自底向上的实现将每个非起点状态只计算一次。

若费用整数位数很大，整数加法和比较也有相应成本；上表采用算法课程中常见的单位成本模型。

## 易错点

| 常见错误 | 正确理解与修正 |
| --- | --- |
| 把位置n−1当成楼顶 | 它仍是收费台阶；楼顶是位置n |
| 在主实现转移中加cost[i] | 本文状态尚未支付当前费用，应加来源台阶费用；i=n时cost[i]还会越界 |
| 只允许从位置0起步 | 位置1也可直接选择为起点，因此dp[0]与dp[1]都为0 |
| 认为起点免费，所以离开起点也不用付费 | 免费的是初始站位，离开起点仍需支付对应费用 |
| 跨过的台阶也支付费用 | 只支付实际离开的台阶，未停留的台阶不支付 |
| 以到达状态初始化，却用已支付状态的公式或返回值 | 两种定义各自有效，但必须成套匹配，不能混用 |
| 直接返回dp[n−1] | 本文最终状态是dp[n]，还要完成到楼顶的最后一步 |
| 认为两个台阶必须另写特判 | 统一转移自然给出min(cost[0], cost[1]) |
| 先覆盖滚动旧状态，再计算current | 当前计算需要两个旧状态，应先计算新值，再推进变量 |
| 用加法合并两种来源 | 本题求最低费用，应取min；统计路径条数才是另一种问题 |

## 课堂练习

### 基础核对

分别写出下列费用列表对应的楼顶位置与最小费用：

| cost |
| --- |
| `[10, 15, 20]` |
| `[5, 8]` |
| `[8, 5]` |
| `[0, 0, 0]` |
| `[1, 2, 100]` |

::: details 参考答案

| cost | 楼顶位置 | 最小费用 |
| --- | ---: | ---: |
| `[10, 15, 20]` | 3 | 15 |
| `[5, 8]` | 2 | 5 |
| `[8, 5]` | 2 | 5 |
| `[0, 0, 0]` | 3 | 0 |
| `[1, 2, 100]` | 3 | 2 |

两个收费台阶时，可以从任一位置直接到达楼顶，答案取两项费用的较小值；全零费用时，所有合法路径的总费用都是0。
:::

### 过程推演

给定 `cost = [4, 1, 6, 2, 3]`：

1. 写出包括起点与楼顶在内的完整dp表。
2. 展开计算最后一个状态的两个候选。
3. 给出一条最优路径，并列出实际支付的费用。

::: details 参考答案

| 位置i | 0 | 1 | 2 | 3 | 4 | 5（楼顶） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| dp[i] | 0 | 0 | 1 | 1 | 3 | **3** |

最后一步：

$$
dp[5]=\min(dp[4]+cost[4],\ dp[3]+cost[3])
=\min(3+3,\ 1+2)=3.
$$

最优路径为 `1 → 3 → 5（楼顶）`，支付 `cost[1] + cost[3] = 1 + 2 = 3`。
:::

### 进阶思考

1. 主示例中，本文的dp表为 `[0, 0, 10, 15]`。若改用“到达并已支付当前阶费用”的paid状态，对应表与最终答案是什么？
2. 若只把最后一项费用改得很大，答案是否一定变大？给出一个例子并解释。
3. 若前进规则改为每次走1、2或3阶，但起点仍只允许0或1，转移和边界应怎样处理？

::: details 参考答案

1. `paid = [10, 15, 30]`，只包含三个收费台阶。答案为 `min(paid[2], paid[1]) = 15`。paid表的初始值、公式和返回值与dp不同，但给出同一最优费用。
2. 不一定。`[10, 15, 20]` 改为 `[10, 15, 1000]`，仍可从1直接到3，答案仍为15，因为无需离开位置2。
3. 对i≥2，枚举步长s∈{1,2,3}，只保留i−s≥0的来源：

   $$
   dp[i]=\min_{\substack{s\in\{1,2,3\}\\i-s\geq0}}
   \bigl(dp[i-s]+cost[i-s]\bigr).
   $$

   仍有 `dp[0] = dp[1] = 0`，但不能把 `dp[2]` 也初始化为0，因为它不是新增的免费起点。依次计算i=2到n，答案仍为 `dp[n]`。该变式只改变合法步长，不自动改变起点集合。
:::
